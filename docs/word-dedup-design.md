> 🚨🚨🚨 **เจ้าของคลังสั่งเองว่าเรื่องนี้ "สำคัญมากกกกกกก กลัวตกหล่น" — จึงแยกเป็นไฟล์ของตัวเอง ไม่ซ่อนเป็นหัวข้อท้ายไฟล์ยาว**
> 🎯 **เจ้าของกำหนดกรอบไว้ว่า:** _"เราต้องการแบบที่ดีที่สุด โดยไม่สนว่าต้องเขียน code มากแค่ไหน"_ → **ห้ามเลือกทางลัด**
> 📅 บันทึก 31 ก.ค. 2569 · ยังไม่ลงมือทำ รอทำพร้อมระบบใยแมงมุม

## ๑ · ปัญหาที่ต้องแก้ (เจ้าของจับได้เอง)

> _"คือมันซ้ำแค่วลี แต่ทั้งชื่อนิยายก็ไม่ซ้ำนะ และอาจจะไปหมวดใหม่ได้ ดังนั้นมันต้องนำเข้าแบบไหนล่ะ"_
> _"เราสงสัยว่าตอนที่เราจะนำเข้าบนเว็บตรง ๆ มันต้องไปแก้ code อะไรไหม ไม่งั้นคำซ้ำ โดนเด้งออกเลยนะ ทั้ง ๆ ที่ชื่อนิยายคนละเรื่อง"_

### จุดที่เป็นปัญหาในโค้ดตอนนี้

`components/handlers/review.js` เมธอด `_save`:
```js
const libSet = new Set(app.state.library.map((w) => (w.text || '').trim()));
const words = allWords.filter((w) => !libSet.has(w.text));
const skipped = allWords.length - words.length;
```

**เทียบด้วยตัวข้อความอย่างเดียว — ไม่ดูหมวด ไม่ดูกิ่ง ไม่ดูชื่อนิยาย ไม่ดูความหมาย**
ข้อความตรงกันเป๊ะ = ข้ามทันที

### ทำไมถึงอันตรายที่สุด

**มันเงียบ** — ระบบรายงานว่า _"ข้ามไป N คำเพราะซ้ำ"_ ซึ่งฟังดูเหมือนทำงานถูกต้อง
เจ้าของคลังจะไม่มีทางรู้เลยว่าเพิ่งเสียคำไป จนกว่าจะไปนั่งไล่ดูเองทีละคำ

### ตัวเลขจริงที่วัดได้ (31 ก.ค. 2569)

| | |
|---|---|
| คลังเดิม (เสียงกระซิบจากความมืด) | 1,060 คำ |
| คลังชุดใหม่ (คินดะอิจิยอดนักสืบ ตอน บทเพลงปีศาจ) | 1,891 คำ |
| **ซ้ำข้ามเล่ม** | **137 คำ** ← จะโดนเด้งทั้งหมดถ้านำเข้าผ่านเว็บตอนนี้ |
| ในนั้น **มีกิ่งที่คลังเดิมยังไม่มี** | **22 คำ** ← เสียกิ่งใหม่ไปฟรี ๆ |
| คำในคลังเดิมที่ถูกเก็บเป็น **2 แถวเพราะอยู่ 2 หมวด** | **29 คำ** |

**29 แถวคู่นั้นเข้าคลังได้เพราะนำเข้าจากไฟล์โดยตรง ไม่ได้ผ่านหน้าเว็บ** — ถ้าวันนี้กดบันทึกผ่านเว็บจะโดนข้ามหมด

ตัวอย่างคำที่ถูกแตกเป็น 2 แถว:
| คำ | แถวที่ 1 | แถวที่ 2 |
|---|---|---|
| `ล้มระเนระนาด` | หมวด 1 · สภาพความพัง | หมวด 3 · การเสียหลัก |
| `ไม่ทันกาล` | หมวด 1 · ช่วงเวลา | หมวด 6 · ความฉุกละหุก |
| `ท้องฟ้าคำรามเสียงดังลั่น` | หมวด 1 · ท้องฟ้า | หมวด 4 · เสียงสภาพอากาศ |

**และ 2 แถวนี้ไม่รู้จักกันเลย** — แก้ความหมายแถวหนึ่ง อีกแถวยังเป็นของเก่า

## ๒ · รูปแบบที่ดีที่สุด — "ไม่มีคำว่าข้าม มีแต่สร้างใหม่กับเพิ่มเส้น"

### หลักคิดหลัก

🔑 **คำซ้ำไม่ใช่ของเสีย แต่คือคำเดียวกันที่เจอในบริบทใหม่**
(ตรงกับที่เจ้าของสั่งไว้ตั้งแต่ 26 ก.ค.: _"ตอนที่รวม 2 คลัง มันจะมีคำซ้ำเยอะมาก **ห้ามลบ** แต่ต้องโยงตามระบบใยแมงมุม"_)

ดังนั้นตอนเจอคำซ้ำ **ระบบไม่ต้องตัดสินใจว่าจะเก็บหรือทิ้ง** เพราะทั้งสองทางผิด
- เก็บทั้งคู่ = ได้แถวซ้ำที่ไม่รู้จักกัน (ปัญหาเดิมของ 29 คำ)
- ทิ้งอันใหม่ = เสียกิ่ง/นิยาย/ความหมายที่อันใหม่มี (ปัญหาที่กำลังจะเกิดกับ 137 คำ)

**ทางที่ถูกคือทางที่สาม: เก็บคำไว้แถวเดียว แล้วเพิ่มเฉพาะ "เส้นเชื่อม" ที่ยังไม่มี**

### โครงข้อมูล

```
wb_words                    1 แถว = 1 คำ (ไม่ซ้ำ)
  id · text · kind · created_at
  ⚠️ ไม่มี category_id · ไม่มี subpath · ไม่มี novel อยู่ในนี้อีกต่อไป
     (คงคอลัมน์เดิมไว้เขียนคู่กันเพื่อไม่ให้หน้าเว็บเดิมพัง — ดูข้อ ๕)

wb_word_branches            1 แถว = คำ 1 คำ ติดกิ่ง 1 กิ่ง
  word_id · branch_code · category_id · added_at · source
  🔑 category_id อยู่ที่ "เส้น" ไม่ใช่ที่ "คำ" → คำเดียวข้ามหมวดได้จริง

wb_word_novels              1 แถว = คำ 1 คำ เจอในนิยาย 1 เรื่อง
  word_id · novel · first_seen_at

wb_word_links               1 แถว = คำลูก 1 คำ ตัดมาจากวลีแม่ 1 วลี
  child_word_id · parent_word_id · added_at
  🔑 ผูกด้วย id ไม่ใช่ข้อความ · ไม่มีเส้นเลย = "เก็บมาเอง ไม่ได้ตัดจากไหน"

wb_word_meanings            1 แถว = 1 ความหมายของคำนั้น
  word_id · meaning · added_at
  🔑 เป็นตารางแยก ไม่ใช่ช่องเดียวในคำ → เพิ่มความหมายใหม่ได้โดยไม่ทับของเดิม
```

### ขั้นตอนตอนนำเข้าคำ 1 คำ

```
1. หาว่ามีคำนี้ในคลังแล้วหรือยัง (เทียบข้อความหลังทำให้เป็นมาตรฐาน — ดูข้อ ๓)

2. ยังไม่มี  → สร้างคำใหม่ + สร้างเส้นทั้งหมด (กิ่ง · นิยาย · วลีแม่ · ความหมาย)

3. มีอยู่แล้ว → ❌ ห้ามข้าม ❌ ห้ามสร้างแถวใหม่
                ✅ ไล่เพิ่มเฉพาะเส้นที่ยังไม่มี:
                   · กิ่งไหนยังไม่ติด        → เพิ่มเส้นกิ่ง
                   · นิยายเรื่องไหนยังไม่มี   → เพิ่มเส้นนิยาย
                   · วลีแม่ไหนยังไม่โยง      → เพิ่มเส้นวลีแม่
                   · ความหมายไหนยังไม่มี     → เพิ่มความหมาย (ไม่ทับของเดิม)
                ✅ รายงานให้ผู้ใช้เห็นว่า "คำนี้มีอยู่แล้ว เพิ่มให้ N กิ่ง / M เรื่อง"
```

🔴 **คำว่า "ข้าม" ต้องหายไปจากระบบทั้งหมด** — ทุกคำที่ส่งเข้ามาต้องมีผลลัพธ์เสมอ
ไม่ "สร้างคำใหม่" ก็ "เพิ่มเส้นให้คำเดิม" · ไม่มีทางที่ข้อมูลจะหายเงียบ ๆ อีก

## ๓ · การเทียบข้อความ — เทียบยังไงถึงจะถูก

### ต้องทำให้เป็นมาตรฐานก่อนเทียบเสมอ

| ทำอะไร | ทำไม |
|---|---|
| ตัดช่องว่างหัว-ท้าย | `"เสียว "` กับ `"เสียว"` ต้องเป็นคำเดียวกัน |
| ยุบช่องว่างซ้อนให้เหลือช่องเดียว | ข้อความที่พิมพ์ด้วยเสียงมักมีช่องว่างเกิน |
| **ห้ามแปลงตัวอักษรใด ๆ นอกจากนี้** | 🚨 คำไทยที่ต่างกันแค่วรรณยุกต์คือคนละคำ (`เต็มเหนียว` ≠ `เต็มเหนี่ยว`) |

🔴 **ห้ามเทียบแบบ "คล้ายกัน" หรือ "ใกล้เคียง" เด็ดขาด** — คลังนี้เก็บคำงามที่ต่างกันเพียงเสียงเดียวได้จริง
การเดาว่าสองคำนี้น่าจะเป็นคำเดียวกัน = เสี่ยงยุบคำที่เจ้าของตั้งใจแยก

### เทียบด้วยอะไร

**เทียบด้วย "ข้อความ" อย่างเดียวก็ถูกแล้ว — แต่ต้องเปลี่ยนสิ่งที่ทำหลังจากเจอว่าซ้ำ**

นี่คือจุดที่คนมักเข้าใจผิด: ปัญหาไม่ได้อยู่ที่ *วิธีเทียบ* แต่อยู่ที่ *สิ่งที่ทำเมื่อเทียบแล้วเจอ*
ระบบเดิมเจอซ้ำแล้ว "ทิ้ง" · ระบบใหม่เจอซ้ำแล้ว "เพิ่มเส้น"

⚠️ **ทางลัดที่เคยคิดไว้แล้วตัดทิ้ง:** เปลี่ยนตัวเทียบเป็น "ข้อความ + หมวด"
→ แก้ได้แค่ครึ่งเดียว เพราะคำเดียวกัน หมวดเดียวกัน แต่มาจากนิยายคนละเรื่อง **ก็ยังโดนเด้งอยู่ดี**
→ และยังทิ้งปัญหา "แถวซ้ำที่ไม่รู้จักกัน" ไว้เหมือนเดิม
→ **เจ้าของสั่งให้ทำแบบดีที่สุด ไม่เอาทางลัด**

### กรณีพิเศษที่ต้องระวัง

1. **บทบรรยายยาว (หมวด 15)** — ยาวสุด 182 ตัวอักษร · การเทียบข้อความเป๊ะยังใช้ได้ปกติ ไม่ต้องมีกฎพิเศษ
   ⚠️ แต่กฎเดิมในระบบที่ว่า _"คำยาวเกิน 24 ตัวอักษร ไม่นับซ้ำ"_ **ต้องเอาออก** เพราะขัดกับหลักใหม่
   (ของเดิมมีไว้กันบทบรรยายยาวถูกมองว่าซ้ำกันมั่ว ๆ ซึ่งพอเปลี่ยนเป็นระบบเพิ่มเส้นแล้วไม่จำเป็นอีก)

2. **คำที่เป็นทั้งวลีตั้งต้นและคำสกัด** — เช่น `กรอกตาเพ่งพินิจ` เป็นวลีตั้งต้น ส่วน `กรอกตา` เป็นคำที่สกัดจากมัน
   ทั้งคู่เป็นคนละแถวถูกต้องแล้ว **ไม่ใช่คำซ้ำ** · ความสัมพันธ์เก็บใน `wb_word_links`

3. **คำเดียวกันที่สกัดมาจากหลายวลี** — มี 52 คำในคลังเดิมที่เป็นแบบนี้
   → 1 แถว + หลายเส้นใน `wb_word_links` ไม่ใช่หลายแถว

## ๔ · การยุบ 29 แถวคู่ที่มีอยู่แล้ว (งานย้ายข้อมูลครั้งเดียว)

29 คำในคลังเดิมถูกเก็บเป็น 2 แถวเพราะข้อจำกัดเดิม ตอนย้ายมาระบบใหม่ต้องยุบเป็นแถวเดียว

```
ก่อนยุบ:  ล้มระเนระนาด (แถว A) → หมวด 1 · สภาพความพัง
          ล้มระเนระนาด (แถว B) → หมวด 3 · การเสียหลัก

หลังยุบ:  ล้มระเนระนาด (แถวเดียว)
            ├─ เส้นกิ่ง → หมวด 1 · สภาพความพัง
            └─ เส้นกิ่ง → หมวด 3 · การเสียหลัก
```

🔒 **กฎการยุบ — ห้ามให้อะไรหายแม้แต่อย่างเดียว**
- **กิ่ง** — เอาของทุกแถวมารวมกัน (union) ไม่ใช่เลือกแถวใดแถวหนึ่ง
- **ความหมาย** — ถ้าสองแถวเขียนไม่เหมือนกัน **เก็บทั้งคู่เป็นคนละความหมาย** ห้ามเลือกอันใดอันหนึ่ง
- **วลีแม่ · นิยาย** — รวมกันทั้งหมด
- **ต้องนับก่อน-หลังทุกครั้ง** ว่าจำนวนเส้นกิ่งรวมเท่าเดิม

## ๕ · ของเดิมต้องไม่พัง

หน้าเว็บทุกหน้าตอนนี้อ่านจาก `wb_words.category_id` · `.subpath` · `.subpaths` · `.novel` โดยตรง

🛡 **วิธีที่ปลอดภัย = เขียนคู่กันเสมอ (แบบเดียวกับที่ระบบเคยทำกับ `subpath`/`subpaths` มาแล้ว)**
- ตารางเส้นเชื่อมเป็น "ความจริงตัวหลัก"
- แต่ยังเขียนค่าลง `wb_words` ตามเดิมด้วย: `category_id`/`subpath` = เส้นแรก · `subpaths` = ทุกเส้นในหมวดหลัก · `novel` = เรื่องแรก
- → **หน้าเว็บเดิมทำงานเหมือนเดิมทุกหน้า** โดยไม่ต้องแก้พร้อมกันทีเดียว
- แล้วค่อยทยอยย้ายทีละหน้าให้อ่านจากตารางเส้นเชื่อมแทน
