## 6. 🏆 ทักษะ web dev ระดับเทพ (best practices จากที่ทำมาจริง)
- **Offline-first sync** — localStorage + debounce push + **merge เทียบเวลา (`_t` timestamp) ไม่ใช่ last-write-wins ทื่อๆ** + **tombstone `_del:true` แทน delete จริง** (กันติ๊กออกแล้วเด้งกลับข้ามเครื่อง) + flush ตอนปิดแอป · ทุกปุ่ม **immutable update** (สร้าง object ใหม่ ไม่ mutate)
- **Optimistic UI** — อัปเดต state ทันที → ยิง API เบื้องหลัง `.catch()` → revert ถ้าล้มเหลว · มี confirmUndo ก่อนทุกการยกเลิก/ลด/ลบ
- 🚨 **โหลดครั้งเดียว (load-once)** — หน้าที่โหลด list/data ห้าม fetch ใหม่ทุกครั้งที่เข้า · pattern: `loadCache(key)` seed state ตอน mount (ไม่ skeleton ซ้ำ) → `load(force)`: ถ้ามี cache สด (`Date.now()-c.ts < CACHE_TTL`) และไม่ force = **return ไม่ยิง server** · `saveCache` หลัง fetch สำเร็จ · invalidate cache ตอน mutation · helper กลางใช้ข้าม domain
- **Realtime** — **1 channel ต่อ 1 ตาราง** (หลาย channel ซ้อนตารางเดียว = ส่ง event ไม่ครบ ติดๆดับๆ) · **refetch ผ่าน API เมื่อได้ event ดีกว่า patch จาก payload** · subscription deps นิ่ง (ไม่ churn)
- 🚨 **Sticky header ห้ามมีช่องว่าง** — sticky ใน scroll container ที่มี `padding` (เช่น `p-6`=24px) ถ้าใช้ `top:0` จะ**ติดต่ำลง 24px** (=padding-top) · **สูตรถูก: `top:'-24px'` + `margin:'0 -24px Xpx'` + `padding:'12px 24px Ypx'`** · bg = สีพื้นหน้า · พิสูจน์: `getBoundingClientRect().top` ของ sticky = ของ scroll container (gap=0)
- 🚨🚨 **`margin:0 auto` + พ่อเป็น flex = หน้าเว็บหดเงียบ ๆ** — ใน flex ตัว `margin:auto` บนแกนขวางจะ**ยกเลิกการ stretch** แล้วย่อกล่องลงเท่า fit-content ไม่มี error ไม่มีคำเตือน (เจอจริง มูลค่ายาคืน 2026-08-05: หน้าเว็บหด 1360 → **1013px**) · **แก้: ใส่ `width:100%` ให้กล่องที่ใช้ `max-width + margin:0 auto` ทุกตัวที่พ่อเป็น flex** · ข้อยกเว้น: พ่อเป็นบล็อกธรรมดาไม่ต้องใส่
- 🚨 **จะให้กล่องลูกเลื่อนในตัวเอง (`overflow-y:auto`) พ่อทุกชั้นต้องมีความสูงที่แน่นอน** — ชั้นไหนเป็น `flex:1 0 auto` (ห้ามหด) จะทำให้ลูกไม่รู้ความสูงตัวเอง แล้วยืดตามเนื้อหาไปเรื่อย ๆ จนทั้งหน้าเลื่อนแทน · **สูตร: ทุกชั้นตั้งแต่ scroll container ลงมาต้องเป็น `flex:1;min-height:0`** แล้วชั้นสุดท้ายค่อยใส่ `overflow-y:auto` · ใส่ `min-height:XXXpx` ที่ตัวหน้าไว้เป็นทางหนีตอนจอเตี้ยมาก (ให้กลับไปเลื่อนทั้งหน้าแทนการบีบจนอ่านไม่ได้)
- **ระยะ sticky ที่ต้องอิงความสูงของอีกก้อน = วัดสดด้วย `ResizeObserver` เขียนลง CSS variable** อย่าตั้งเลขตายตัว (แถบที่มี `flex-wrap` จะขึ้นบรรทัดใหม่เองเมื่อจอแคบ ความสูงเปลี่ยน) · ผูก observer ผ่าน **ref แบบฟังก์ชัน** จะได้ต่อ/ถอดถูกจังหวะตอนของโผล่/หายจากจอ
- **ตรวจ "มีเมาส์จริงไหม" ใช้ `matchMedia('(pointer: fine)')`** ไม่ใช่เดาจากความกว้างจอ (แท็บเล็ตแนวนอน 1024px จะหลุด) · **ต้องฟัง event `change` ด้วย** ไม่ใช่วัดครั้งเดียวจบ เพราะเสียบเมาส์/ถอดจากแท่นวางค่าเปลี่ยนกลางคันได้ · โน้ตบุ๊กจอสัมผัสที่ต่อเมาส์ยังนับเป็น fine (ดูตัวชี้หลัก)
- **ไอคอนในปุ่มใช้ SVG inline ไม่ใช่ตัวอักษรพิเศษ** (`⤓` `⌫` ฯลฯ ขึ้นกับฟอนต์ของเครื่อง บางเครื่องกลายเป็นสี่เหลี่ยมว่าง)
- 🚨 **เช็ค Chrome จริง แต่ไม่ต้องเทสทุกครั้ง** — เทสเองเฉพาะ (1) พี่กันสั่งให้เทส (2) จุดที่เป็นระบบ/ฟีเจอร์ใหม่ · นอกนั้นถามพี่กัน/ให้พี่กันเทสเอง · 🔴 **หน้าที่เป็นส่วนของแอปจริง (มี auth/ข้อมูลจริง) = ต้องเทส "หน้าจริง" ในเบราว์เซอร์จริง ห้ามสร้าง mock HTML มาเทสแทน** (mock ผ่านหมดแต่เว็บจริงมีบั๊ก) · เทสที่**สัดส่วนจริง** (เดสก์ท็อป landscape มี sidebar ~1360px ถ้าเป็นเว็บเดสก์ท็อป / portrait ถ้าเป็น mobile app)
- **Security** — RLS ทุกตาราง (ลบ policy "allow all" ก่อน prod) · ไม่มี secret ใน client · privileged op ผ่าน API route (admin client) · escape XSS · CSP headers (ไม่มี unsafe-eval) · storage private + signed URL · rate limit brute force login
- **Performance** — lazy render (30 + ดูเพิ่ม) · debounce search 200-500ms · useMemo คำนวณหนัก · **CSS class แทน inline** เมื่อมี element เยอะ · materialized view + pg_cron สำหรับ query ช้า · virtual scroll · **Cache-Control no-store** แก้ error 500 chunk หาย
- **Mobile/PWA** — mobile-first · touch target ใหญ่ · `dvh` units · manifest+icon · **เทสเครื่องจริง** (headless จับ GPU freeze/paint ไม่ได้)
- **ไทยเฉพาะ** — วันที่ **timezone +7** (อย่าลืมบวก) · ฝังฟอนต์ไทยเอง (woff2 @font-face กันเครื่องไม่มีฟอนต์) · print-color-adjust บังคับพิมพ์สี
- **Deploy** — **Cloudflare Pages = HTML/static · Workers = Next.js มี server** · ตั้ง env vars บน host ให้ตรง .env.local · **Next.js 16 ห้าม rename middleware.ts→proxy.ts บน Cloudflare** · changelog generator อัตโนมัติ (ห้ามแก้ไฟล์ changelog มือ)
- **Email** — Resend · **fire-and-forget** (เมลล้มไม่ทำให้ flow พัง try/catch) · โลโก้ **PNG hosted (ไม่ใช่ inline SVG)** สำหรับ Gmail · Gmail บังคับรูปเต็มกล่อง → ใช้รูปจัตุรัส · เมลอ่านรูปจาก localhost ไม่ได้ (เห็นหลัง deploy)
- **File org** — แยกไฟล์ใหญ่ได้ (verify concat กลับ byte-identical) · classic scripts แชร์ global env · ⚠️ **content-visibility ทำ popup ค้าง** (diff หาเจอ ไม่ใช่การแยกไฟล์)
- 🚨 **Next.js dev/build** — **ห้ามรัน `npm run build` ขณะ `npm run dev` เปิดอยู่** → .next ชนกัน (Cannot find module './xxx.js') · ต้องหยุด dev + ลบ .next ก่อน build (เจอ 2026-07-17)
- 🚨🚨 **เซิร์ฟเวอร์ทดสอบ (localhost) เปิดได้ทีละตัวเดียวเท่านั้น · วันไหนเริ่มพอร์ตไหน ใช้พอร์ตนั้นทั้งวัน** (พี่กันสั่ง 10 ส.ค. 2569 *"เอาแค่อันเดียว อย่าเปิดสองโลคอลสิวะ"* · *"เธอรันโลคอลเลขไหนมาแล้วในวันนั้นๆ ให้ใช้อันเดิม"*)
  - **ก่อนเปิดทุกครั้ง เช็คก่อนว่ามีตัวไหนรันอยู่แล้ว** (`netstat -ano | grep LISTENING | grep :30`) · **มีอยู่แล้ว = ใช้ตัวนั้นเทส ห้ามเปิดเพิ่ม ห้ามปิดของพี่กันแล้วเปิดใหม่**
  - **ห้ามเปิด ๆ ปิด ๆ สลับพอร์ตไปมาเด็ดขาด** — พี่กันเปิดเว็บค้างไว้อยู่ พอแคลร์ปิด พี่กันเจอ ERR_CONNECTION_REFUSED แล้วต้องมาถามใหม่ เสียเวลาหลายรอบ (เคยพลาด: เปิด 3100 คู่กับ 3000 แล้วปิดทิ้งโดยไม่บอก)
  - จดพอร์ตของวันไว้ในไฟล์ session/CLAUDE.md ของโปรเจกต์ ครั้งหน้ามาต่อจะได้ใช้ตัวเดิม
- **Debug** — Supabase MCP execute_sql แยก backend/frontend · SWC strict จับ bug ที่ Babel ซ่อน (TDZ/ซ้ำ) · เทสหลายเบราว์เซอร์จับ GPU-specific freeze

## 6.6 🩺 คิดแบบนักออกแบบเว็บทางการแพทย์ — มาตรฐานงานทุกชิ้น

> พี่กันสั่งไว้ 19 ส.ค. 2569 · **อ่านข้อนี้ก่อนออกแบบหรือแก้หน้าจอทุกครั้ง**
> *"เราอยากให้เธอคิดว่าเธอเป็นนักออกแบบเว็บทางการแพทย์ ที่ข้อมูลจะต้องครบ สวย
> ผู้ใช้ใช้แล้วไม่งง ไม่ด่า และทุกอย่างมันต้อง perfectionist"*

### เกณฑ์ 4 ข้อที่ทุกหน้าต้องผ่าน

| | เกณฑ์ | แปลว่าอะไร |
|---|---|---|
| **ครบ** | ข้อมูลที่เก็บมาต้องไปโผล่ที่หน้าจอ | เก็บแล้วไม่แสดง = เสียเวลาคนกรอกฟรี |
| **สวย** | จัดวางเป็นระเบียบ สีมีความหมาย ไม่ใช่ตกแต่ง | ตารางดิบๆ ไม่ใช่งานออกแบบ |
| **ไม่งง** | คนเปิดมาครั้งแรกต้องรู้ว่ากำลังดูอะไร | ต้องเดา ต้องถาม = ออกแบบพลาด |
| **เนี้ยบ** | ไม่มีจุดค้าง ไม่มีของครึ่งๆ กลางๆ | ทำครึ่งเดียวแล้วบอกว่าเสร็จ ไม่นับ |

### 🔴 กฎที่ตกผลึกจากงานจริง

**1. ข้อมูลแต่ละชิ้นต้องไปอยู่บ้านของมัน ห้ามกองรวมเป็นตารางยาว**

พลาดจริง 19 ส.ค. 2569 — พี่กันสั่งว่า "ข้อมูลแรกรับต้องแสดงในแฟ้มทั้งหมด"
แคลร์เอาทุกช่องมากางเป็นตารางยาวก้อนเดียว พี่กันทักว่า
> *"หมายถึง ถ้า eGFR ก็ไปกราฟของมัน ชื่อ สิทธิรักษาก็ไปที่ส่วนข้อมูลส่วนตัว หรือยาก็ไปส่วนยา"*

· ค่าที่มีประวัติตามเวลา → **ไปอยู่กับกราฟของมัน**
· ข้อมูลตัวบุคคล → ไปอยู่ส่วนข้อมูลส่วนตัว
· ยา → ไปอยู่ส่วนยา · การแพ้ → ไปอยู่ส่วนความปลอดภัย
· **อยากดูทั้งหมดพร้อมกัน = ทำปุ่มกดแล้วเด้งหน้าต่างขึ้นมา** ไม่ใช่กางไว้บนหน้า

**2. ค่าอะไรที่วัดซ้ำได้ตามเวลา ต้องมีกราฟ**

ตัวเลขล่าสุดตัวเดียวบอกไม่ได้ว่าดีขึ้นหรือแย่ลง ซึ่งเป็นสิ่งที่คนดูแลอยากรู้ที่สุด
เก็บค่าไว้ทุกครั้งแล้วไม่วาดให้ดู = เก็บไปทำไม

**3. ทุกตัวเลขต้องบอกความหมาย ไม่ใช่โยนเลขเปล่า**

· ทาสีตามเกณฑ์จริง ไล่โทนต่อเนื่องไม่ข้ามขั้น
· มีหน่วยกำกับเสมอ · บอกว่าเทียบกับอะไร (ครั้งก่อน / แรกรับ / เป้าหมาย)
· 🔴 **ทุกเกณฑ์ต้องบอกที่มา** ว่ามาจากแนวทางฉบับไหนหน้าไหน หรือพี่กันกำหนดเอง
  สองอย่างนี้น้ำหนักไม่เท่ากัน คนอ่านต้องแยกออก

**4. ช่องที่ยังไม่มีข้อมูล ต้องเขียนว่ายังไม่ได้บันทึก**

ปล่อยว่างไว้เฉยๆ คนอ่านแยกไม่ออกว่า "ไม่มีข้อมูล" กับ "ระบบพัง"

**5. หน้าที่ไม่มีข้อมูลต้องเหลือโครง** การ์ดเป็น 0 หัวตารางยังอยู่ ไม่ใช่หายทั้งหน้า

**6. เก็บข้อมูลเกินดีกว่าขาด**

พี่กันสั่ง 19 ส.ค. 2569 — *"เราว่ามีตารางเก็บข้อมูลที่เกิน ดีกว่าขาด"*
เพราะข้อมูลที่ไม่ได้เก็บตั้งแต่แรก **ย้อนกลับไปเก็บไม่ได้** ตอนงานใกล้เสร็จค่อยทบทวนว่าจะตัดช่องไหน

**7. สีต้องพาสเทล นุ่มตา** พี่กันย้ำหลายรอบ
สีจัดจ้านใช้เฉพาะตอนเตือนจริงๆ · ที่เหลือให้อ่านสบายตาเพราะทีมต้องจ้องทั้งวัน

**8. ทำหน้าจอ = ทำมอคอัปให้ดูก่อนเสมอ ห้ามลงเว็บเลย**

🔴 พลาดจริง 19 ส.ค. 2569 พี่กันขอมอคอัป แคลร์ลงโค้ดในเว็บไปเลย
> *"แต่จริงๆที่ให้เธอทำคือมอคอัปนะ 55555 เธอทำลงเว็บซะงั้น"*

· ทำเป็นไฟล์ HTML เดี่ยวใน `mockups/` แล้วส่งให้ดู
· **เสนอหลายแบบให้เลือก** อย่างน้อย 2 ถึง 3 แบบ พร้อมบอกข้อดีข้อเสียของแต่ละแบบ
· ห้ามใช้ฟอนต์จาก CDN แม้แต่ในมอคอัป (เน็ตโรงพยาบาลไม่นิ่ง)
· ใช้ชุดสีจริงของระบบ จะได้ไม่หลอกตา
· 🔑 **มอคอัปที่พี่กันเคาะแล้ว = สัญญา ทำตามเป๊ะ**

**9. ของที่ทำไปแล้วห้ามเอาออกเอง** พี่กันย้ำ 19 ส.ค. 2569
> *"ไม่ได้ให้เอาอันที่ทำแล้วออกนะ ทำมาแล้วก็ทำมา แต่ก็ทำมอคอัปให้เราดูรูปแบบอื่นๆด้วย"*

เสนอแบบใหม่ = ทำเพิ่มให้เลือก ไม่ใช่ลบของเดิมทิ้งก่อน

## 6.1 📊 ตารางต้องเป็น "ตารางจริง" เท่านั้น

**พี่กันสั่ง 1 ก.ย. 2569: "ตั้งเป็นกฎ ต้องสร้างตารางจริงเท่านั้น"**
หลังจากเพิ่งรู้ว่าปัญหาตารางที่ด่ามาทั้งหมดมาจากการไม่ได้ใช้ตารางจริง

- 🔴🔴🔴 **ข้อมูลที่เป็นแถวเป็นคอลัมน์ ต้องใช้ `<table>` `<thead>` `<tbody>` `<tr>` `<td>` เท่านั้น**
  ห้ามเอากล่อง (`<div>` + flex) มาวางเรียงให้ดูเหมือนตาราง

**ทำไม** — ที่เคยเสียเวลาแก้ซ้ำ ๆ เพราะเรื่องพวกนี้ ตารางจริงได้มาฟรีหมด

| เรื่อง | ตารางจริง | กล่องเรียงกัน |
|---|---|---|
| ความกว้างคอลัมน์ | เบราว์เซอร์จัดเอง ทุกแถวตรงแนวเสมอ | ต้องกำหนดเองทุกช่อง เหลื่อมกันบ่อย |
| เส้นแบ่งคอลัมน์เต็มความสูง | `border` ธรรมดา | ต้อง `align-self:stretch !important` แล้วยังพลาดได้ |
| ไฮไลต์แถวตอนชี้ | `tr:hover` | ต้องไล่ทำเองทุกชิ้นในแถว |
| ตรึงหัวตาราง | `thead` + `position:sticky` | ต้องวัดความสูงหัวด้วย ResizeObserver |
| หัวตารางซ้ำทุกหน้าตอนพิมพ์ | `display:table-header-group` | ทำไม่ได้เลย |
| โปรแกรมอ่านจอ | บอกได้ว่าช่องนี้อยู่คอลัมน์ไหน แถวไหน | อ่านเป็นข้อความกองเดียว |

🚨 **ข้อยกเว้นเดียว — การ์ดบนมือถือ** จอแคบเกินกว่าจะแสดงหลายคอลัมน์
   ให้สลับเป็นการ์ดได้ แต่ฝั่งคอมต้องเป็นตารางจริงเสมอ

⚠️ **ถ้าเจอโค้ดเก่าที่ทำเป็นกล่องเรียงกันไว้แล้ว** ให้บอกพี่กันว่าควรรื้อ
   อย่าเขียนกฎเพิ่มซ้อนไปเรื่อย ๆ เพราะจะต้องดูแลสองชุดตลอดไป

## 6.2 📊 CSS กลางของตาราง — ชุดเดียวใช้ทั้งเว็บ

**ต้นแบบ:** เว็บยาคืน `app/globals.css` คลาส `.tbl` (พี่กันย้ำว่าเอาต้นแบบจากหน้ารายการ Lot)

| คลาส | ใช้กับ |
|---|---|
| `.tbl` | โครงเต็ม — หัวตรึง · เส้นแบ่ง · มุมมน · ลูกศรเรียง |
| `.tbl-grid` | เฉพาะเส้นแบ่ง + ไฮไลต์แถว (ตารางที่หัวมีสีของตัวเอง) |
| `.tbl-zebra` | แถวสลับสีจาง |
| `.wrap` | คอลัมน์ที่ยอมให้ขึ้นบรรทัดใหม่ |
| `.ta-r` · `.ta-c` | ชิดขวา · กึ่งกลาง รายคอลัมน์ |

```css
.tbl { width:100%; border-collapse:collapse; table-layout:fixed; --tbl-pad:15px }
.tbl th, .tbl td { box-sizing:border-box; padding:0 12px; vertical-align:middle;
                   text-align:left; white-space:nowrap }
.tbl th:first-child, .tbl td:first-child { padding-left:var(--tbl-pad) }
.tbl th:last-child,  .tbl td:last-child  { padding-right:var(--tbl-pad) }
.tbl th:not(:last-child), .tbl td:not(:last-child) { border-right:1px solid rgba(30,36,32,.06) }
.tbl thead th { position:sticky; top:var(--tbl-top,0px); z-index:3; background:#e3f0e8 }
.tbl thead th.tbl-sort { cursor:pointer; user-select:none }
.tbl thead th.tbl-sort:hover { background:#d5e8dd }
```

🚨 **ค่าเริ่มต้นของทุกช่องคือ `white-space:nowrap`** เคยใส่ `overflow-wrap:anywhere` ให้ทุกช่อง
ผลคือปุ่มกลายเป็น **"แ ก้"** และมูลค่าตกสองบรรทัด · คอลัมน์ที่ต้องตัดบรรทัดใส่คลาส `wrap` เอง

🚨 **ตารางที่ไม่มี `table-layout:fixed` ต้องใช้ `box-shadow:inset` แทน `border-right`**
เส้นขอบจะไปเพิ่มความกว้างอีก 1px ต่อคอลัมน์ ตารางที่ล้นอยู่แล้วยิ่งล้น

🚨🔴 **ห้ามมี `overflow-x` หรือ `max-height` ครอบ `<table>`**
`overflow-x` ทำให้ `overflow-y` กลายเป็น `auto` โดยปริยาย → `position:sticky` ของ `<th>`
ไปผูกกับกรอบนั้นแทนพื้นที่เลื่อนของเว็บ **หัวตารางลอยไปโผล่กลางตาราง**
(เจอทั้งเว็บยาคืนและ ME-DRP)

🚨 **กรอบขาวที่ครอบตารางต้องมี `min-width: fit-content`**
ตารางล็อกความกว้างคอลัมน์ไว้ตายตัว จอที่แคบกว่านั้นถ้ากรอบไม่ยอมกว้างตาม
**ตารางจะทะลุออกนอกกรอบ เห็นเป็นปุ่มกับหัวตารางลอยทับกัน**

### แถบตรึงในกรอบที่มีระยะขอบใน — ต้องทำครบ 3 อย่าง

ขาดข้อใดข้อหนึ่งจะเห็นเป็นบั๊กคนละแบบ

| ต้องทำ | ถ้าไม่ทำ |
|---|---|
| `top` ติดลบเท่าระยะขอบใน (`-16px`) | ติดต่ำลง 16 จุด เกิดร่องให้แถวลอดผ่าน |
| ระยะขอบติดลบ + ระยะในชดเชย | เห็นแถวลอดตรงร่องซ้ายขวา |
| มุมมนตรงกับกรอบ (`14px 14px 0 0`) | มุมเหลี่ยมทับมุมมนของกรอบ |

🚨 **หัวตารางต้องติดที่ `calc(ความสูงแถบหัว - ระยะขอบใน)`**
ตัววัดความสูง (ResizeObserver) วัดความสูงเต็มซึ่งรวมระยะขอบในไว้ด้วย
เอามาใช้ตรง ๆ หัวตารางจะติดต่ำกว่าที่ควร

## 6.3 ⬆️ ลูกศรเรียงลำดับ — เรื่องที่โดนด่า 3 รอบ

**พี่กันสั่งเรื่องนี้ครั้งแรก 27 ส.ค. 2569 แล้วยังต้องทวงอีกที่ ME-DRP 4 ก.ย. 2569**

### ค่ามาตรฐาน — ทุกตารางในทุกเว็บต้องเหมือนกัน

```js
arrow:      on ? (dir === 'asc' ? '↑' : '↓') : '↑↓',
arrowColor: on ? '#2f7d5d' : 'rgba(30,36,32,.34)',
arrowSize:  on ? '19px' : '16px',
```

```
↑↓  ยังไม่ได้เรียงด้วยคอลัมน์นี้   16px  สีจาง
↑   น้อยไปมาก                    19px  เขียวเทล
↓   มากไปน้อย                    19px  เขียวเทล
```

⚠️ **ข้อยกเว้น** — ตารางที่มีคอลัมน์เยอะมาก (คลังยา 15 คอลัมน์) ใช้ **12px**
ลูกศรใหญ่เท่าหน้าอื่นจะดันหัวคอลัมน์จนตารางล้นขอบ

### 🔴🔴🔴 ลูกศรต้องเป็นฟอนต์ Roboto Mono ห้ามปล่อยให้ตกไปที่ Sarabun

พี่กันชี้ให้ดูภาพเทียบสองเว็บแล้วบอกว่า
> *"แหกตาดู ลูกศร / เราไม่ได้บอกให้อ่าน code / ดุรูป"*

**Sarabun วาด ↑↓ ผอมกว่า Roboto Mono ราว 30%** ตั้ง `font-size` เท่ากันเป๊ะก็ยังดูเล็กกว่าอยู่ดี

| ฟอนต์ | ↑↓ ที่ 16px กว้างเท่าไหร่ |
|---|---|
| Roboto Mono (`var(--font-mono)`) | **19.6px** |
| Sarabun | **14.1px** |

```jsx
<span aria-hidden="true" className="tbl-arrow"
      style={{ fontFamily:'var(--font-mono)', fontSize: c.arrowSize, color: c.arrowColor }}>
  {c.arrow}
</span>
```

🚨🔴 **เรื่องนี้อ่านโค้ดหรือวัด `font-size` ไม่มีทางเจอ** เพราะเลขเท่ากันทุกตัว
**ต้องเปิดสองเว็บเทียบด้วยตา** — พี่กันด่าเพราะแคลร์ตอบจากการอ่านโค้ดว่า "ตั้งเท่ากันแล้ว"
ทั้งที่ภาพที่พี่กันส่งมาเห็นชัดว่าไม่เท่า

### 🔴 ลูกศรต้องบอกความจริง — "ลูกศรโกหก" เจอมาแล้ว 2 เว็บ

**อาการ** หน้าจอเรียงวันที่ใหม่→เก่าอยู่แล้วตั้งแต่เปิดหน้า (ฐานส่งมาแบบนั้น)
แต่ตัวแปรที่จำว่า "เรียงด้วยคอลัมน์ไหน" ยังว่าง **ลูกศรจึงแสดง `↑↓` ทั้งที่เรียงอยู่จริง**

```js
// ✅ ยังไม่กดเรียง = ถือว่าเรียงด้วยคอลัมน์ตั้งต้น
const on  = sortKey ? sortKey === c.key : c.key === 'date';
const dir = sortKey ? sortDir : 'desc';
```

🚨 **กดคอลัมน์ตั้งต้นครั้งแรกต้องสลับทิศทันที** ไม่ใช่ตั้งค่าเดิมซ้ำ
ไม่งั้นกดแล้วหน้าจอไม่เปลี่ยนอะไรเลย **ดูเหมือนปุ่มเสีย**

🚨 **ตอนยังไม่ได้กดเรียง ต้องเรียงตั้งต้นเองเสมอ** ไม่ใช่ปล่อยตามลำดับที่ตัวโหลดคืนมา
(ตัวโหลดอาจเอารายการค้างมาต่อท้าย) ไม่งั้น **ลูกศรชี้ ↓ แต่ข้อมูลเรียงมั่ว**

🚨 **ถ้าใช้ `useMemo` ต้องใส่ตัวแปรการเรียงในรายการที่เฝ้าดู** ลืมแล้วกดเรียงข้อมูลไม่ขยับ
(กับดักที่ ME-DRP เขียนเตือนตัวเองไว้แล้ว แล้วก็ยังพลาดซ้ำ)

### ปุ่มล้างการเรียง

โผล่**เฉพาะตอนกดเรียงเองแล้วจริง ๆ** · โทนแดงอิฐ (`#c2543c` บนพื้น `#fdf1ed`)
🚨 **คนละปุ่มกับ "ล้างตัวกรอง"** — การเรียงกับการกรองคนละเรื่องกัน

### 🔑 บทเรียนที่แพงที่สุดของเรื่องนี้

**พี่กันบอกว่าให้ดูรูป = ให้ดูรูป ไม่ใช่ให้ไปอ่านโค้ดแล้วตอบว่าตั้งค่าถูกแล้ว**
ความต่างที่ตาเห็นแต่ตัวเลขบอกไม่ได้ มีจริงและเจอบ่อย — ฟอนต์ · น้ำหนักเส้น · ระยะที่ตาชั่ง
🔴 **พี่กันบอกว่ายังไม่เหมือน = ยังไม่เหมือน** ห้ามเถียงด้วยตัวเลขในโค้ด

## 6.4 🪟 ชั้นหน้าต่างซ้อน — ตารางกลางตัวเดียว ห้ามตั้งเลขเอง

**พี่กันเจอเอง 1 ก.ย. 2569:** กดดูรายการล็อต แล้วกดลบ
> *"เจ้า popup ลบมันดันอยู่ด้านหลัง popup ก่อนหน้า มันควรอยู่บนสุดสิ"*

**ต้นเหตุ** — แต่ละหน้าต่างตั้งเลขชั้นเองตามใจ (20 · 25 · 35 · 40 · 45 · 50 · 60 · 80 · 82)
ป๊อปยืนยันอยู่ 40 ส่วนหน้าต่างรายการล็อตอยู่ 60 **ป๊อปยืนยันจึงถูกทับ**

```js
export const Z = {
  bar:      6,   // แถบเมนู · แถบล่าง · หัวเว็บที่ตรึงไว้
  float:   15,   // ปุ่มลอย เช่น ปุ่มขึ้นบนสุด
  sheet:   20,   // แผ่นเลื่อนขึ้นจากขอบล่าง (มือถือ)
  menu:    29,   // เมนูเล็กที่กางจากช่องในหน้า (ไม่ใช่หน้าต่างซ้อน)
  panel:   32,   // หน้าต่างซ้อนทั่วไป
  over:    52,   // หน้าต่างที่เปิดทับหน้าต่างอื่นได้
  pick:    70,   // ตัวเลือกที่เปิดจากในหน้าต่างซ้อน
  confirm: 85,   // 🚨 ป๊อปยืนยัน — บนสุดของหน้าต่างทั้งหมดเสมอ
  toast:   95,   // ข้อความเด้ง — เหนือทุกอย่าง
};
```

🚨 **ทุกหน้าต่างต้องใช้เลขจากตารางนี้ ห้ามเขียนเลขเองอีก**
🚨 **ฉากหลังใช้เลขตรง ๆ · ตัวกล่องใช้ +1 · ของที่ซ้อนในกล่องใช้ +2**
🚨 **ป๊อปยืนยันต้องสูงกว่าหน้าต่างทุกตัว** มันคือด่านสุดท้ายก่อนข้อมูลหาย
🚨 **ปุ่มลอยต้องต่ำกว่าหน้าต่างซ้อนที่ต่ำที่สุดเสมอ** ไม่งั้นลอยทับแล้วกดโดน

### ฉากหลังห้ามเลื่อนเมื่อมีหน้าต่างซ้อน

| ที่ | ทำอะไร |
|---|---|
| พื้นที่เลื่อนของเว็บ | `overflow-y: hidden` |
| ตัวดักเหตุการณ์ | ห้าม `touchmove` / `wheel` ที่ไม่ได้อยู่ในตัวหน้าต่างเอง |

🚨 **ปิด `overflow` อย่างเดียวพอสำหรับคอม แต่มือถือไม่พอ** เบราว์เซอร์ส่งการเลื่อนต่อ
ให้ตัวที่อยู่ข้างนอก ต้องห้ามที่เหตุการณ์ด้วย
🚨 **ต้องปล่อยให้เลื่อนได้ถ้านิ้วอยู่ในหน้าต่างซ้อนเอง** ตรวจด้วย `closest('[role="dialog"]')`
ไม่งั้นหน้าต่างที่มีเนื้อหายาวเลื่อนดูข้างในไม่ได้เลย
🚨 **เพิ่มหน้าต่างใหม่ต้องเติมชื่อในตัวนับหน้าต่างที่เปิดอยู่ด้วย** ไม่งั้นกฎนี้ไม่ทำงานกับตัวใหม่

## 6.5 ⌨️ ปุ่มทุกปุ่มต้องกดด้วยคีย์บอร์ดได้ + มีชื่อให้โปรแกรมอ่านจอ

มอคอัปมักทำปุ่มเป็น `<div onClick>` ซึ่ง **Tab ไม่ถึงและ Enter ไม่ทำงาน**
เว็บยาคืนเคยมีแบบนี้ **107 จุด** — หน้าบันทึกกด Tab ได้แค่ 4 ชิ้น ทั้งที่กดด้วยเมาส์ได้ 15 ชิ้น

```js
// ตัวช่วยกลาง — คืน onClick + role + tabIndex + onKeyDown ครบในตัวเดียว
export function kb(fn) {
  return { onClick: fn, role: 'button', tabIndex: 0,
           onKeyDown: (e) => { if (e.key === 'Enter' || e.key === ' ') { e.preventDefault(); fn(e); } } };
}
```

```jsx
// ❌ เดิม                          // ✅ ตอนนี้
<div onClick={V.save}>              <div {...kb(V.save)}>
```

🚨 **Space ต้อง `preventDefault`** ไม่งั้นหน้าเลื่อนลงตอนกด
🚨 **ปุ่มใหม่ทุกปุ่มต้องใช้ตัวช่วยนี้ ห้ามเขียน `onClick` เปล่า ๆ อีก**

### โปรแกรมอ่านจอต้องรู้ว่าปุ่มนี้ทำอะไร

| ทำอะไร | ใส่ที่ไหน |
|---|---|
| `aria-label` | **ปุ่มที่มีแต่ไอคอน** (✕ ✎ ⚙ ℹ ✓ ←) ไม่งั้นอ่านว่า "กากบาท" เฉย ๆ |
| `aria-hidden="true"` | ไอคอนที่เป็นแค่เครื่องหมายประกอบข้อความ (ไม่ใช่ปุ่ม) · ชั้นวาดตัวอักษร |
| `role="dialog" aria-modal="true"` | หน้าต่างซ้อนทุกตัว |
| `role="status" aria-live="polite"` | ข้อความเด้ง |
| `role="main"` · `role="navigation"` | กล่องเนื้อหาหลัก · แถบเมนู |
| `role="heading" aria-level="1"` | หัวเรื่องของหน้า |

🚨🔴 **เติม `role=` บนแท็กเดิม ห้ามเปลี่ยนแท็ก**
`<h1>` กับ `<main>` มีสไตล์ตั้งต้นของเบราว์เซอร์ติดมาด้วย (ระยะขอบ ขนาดตัวอักษร)
เปลี่ยนแท็กแล้วหน้าตาขยับทันที ซึ่งผิดกติกาว่างานเก็บกวาดต้องไม่แตะหน้าตาสักพิกเซล

## 6.7 🚨 คอมเมนต์ในโค้ดวางผิดที่ = เว็บพังทั้งเว็บ

**ย้ายมาจากสกิล `button-feedback` เมื่อ 5 ก.ย. 2569** — เดิมอยู่ผิดที่เพราะวันที่เจอบั๊กนี้
กำลังแก้ปุ่มอยู่พอดี แต่กฎนี้ **เกิดได้ทุกที่ที่เขียน JSX** คนที่กำลังทำตารางหรือหน้าสรุป
ไม่มีทางเปิดสกิลปุ่มมาอ่าน

**คอมเมนต์แบบ `{/* */}` วางได้เฉพาะตำแหน่งที่รับ element เท่านั้น**

```jsx
// ❌ พังทันที — วางในแอตทริบิวต์ของแท็ก
<div {/* คำอธิบาย */} style={...}>

// ❌ พังทันที — วางเป็นลูกตัวแรกของ {เงื่อนไข && (
{V.showBar && (
  {/* แถบนี้โผล่เฉพาะตอนมีของค้าง */}
  <div>...</div>
)}

// ❌ พังทันที — วางหลัง ) : ( ของเงื่อนไขสามทาง
// ❌ พังทันที — วางในบล็อก .map() ที่คืนค่าเดียว

// ✅ ถูก — ใช้คอมเมนต์จาวาสคริปต์เหนือบรรทัดแทน
// แถบนี้โผล่เฉพาะตอนมีของค้าง
{V.showBar && (<div>...</div>)}
```

**เหตุผล** — JSX รับ element ได้ชิ้นเดียวในตำแหน่งพวกนั้น **คอมเมนต์นับเป็นอีกชิ้น**

🚨 **อาการคือหน้าเว็บขึ้น error ทั้งใบ ไม่ใช่แค่จุดนั้นเสีย** เจอมาแล้ว 2 รอบในเว็บยาคืน
รอบที่สองเกิดหลังจากเขียนกฎเตือนตัวเองไว้แล้วด้วย

## 6.8 ✍️ ฟอนต์ — Sarabun สำหรับไทย · Roboto Mono สำหรับอังกฤษและตัวเลข

**พี่กันตั้งเป็นมาตรฐานกลาง 5 กันยายน 2569**

> *"ตั้งสารบรรณเป็นฟอนต์ไทย แล้ว roboto mono เป็นฟอนต์อังกฤษ **เป็นตัวหลักเลย**
>  ยกเว้นเว็บบางเว็บจะมีฟอนต์ไทยเป็นหัวเรื่องของตัวเอง อันนี้แยก"*

### กลไก — ทำไมไม่ต้องเขียนเงื่อนไขแยกภาษา

```css
font-family: var(--font-en), var(--font-sarabun), sans-serif;
/*              ↑ Roboto Mono      ↑ ตัวไทยตกมาใช้ตัวนี้เอง */
```

เบราว์เซอร์ไล่ตามลำดับ — ตัวอักษรไหนมีในฟอนต์แรกก็ใช้ตัวนั้น ไม่มีก็ตกมาตัวถัดไป
**Roboto Mono ไม่มีตัวอักษรไทยเลย ภาษาไทยจึงได้ Sarabun เองโดยอัตโนมัติ**
ไม่ต้องเขียนเงื่อนไขแยกภาษาสักบรรทัด

### 🥇 ต้นแบบที่สะอาดที่สุด — HCV Tracker

**HCV เป็นเว็บแรกที่ใช้ระบบนี้** และวางโครงไว้ดีที่สุด ตั้งที่เดียวจบ

```jsx
// app/layout.tsx
const sarabun    = Sarabun({     variable: '--font-sarabun-src', ... });
const robotoMono = Roboto_Mono({ variable: '--font-mono-src',    ... });

<html lang="th" className={`${sarabun.variable} ${robotoMono.variable}`}>
```

```css
/* app/globals.css */
:root { --font-en: var(--font-mono-src); }
html  { font-family: var(--font-en), var(--font-sarabun-src), sans-serif; }
```

🔑 **ตั้งที่ `<html>` ครั้งเดียวแล้วสืบทอดลงมาทั้งเว็บ ไม่ต้องไปแตะที่อื่นเลย**

⚠️ **เว็บยาคืนทำแบบเดียวกันแต่ยากกว่า** เพราะทั้งเว็บวาดด้วยสไตล์ฝังในแท็กราว 600 จุด
จึงต้องใช้ตัวแปลงกลาง (`fontify()` ใน `helpers.js`) แทรก `var(--font-en)` ให้ทุกจุด
**เว็บใหม่ไม่ต้องทำแบบนี้ ใช้ท่าของ HCV ได้เลย**

### 🚨 ตั้งชื่อตัวแปรให้เหมือนกันทุกเว็บ

ตอนนี้ 3 เว็บใช้ชื่อคนละชุด ทำให้ยกโค้ดข้ามเว็บไม่ได้

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `--font-sarabun` | Sarabun ตัวจริงจากตัวโหลดฟอนต์ |
| `--font-mono` | Roboto Mono ตัวจริง |
| **`--font-en`** | **ตัวกลางที่ทุกจุดในเว็บอ้างถึง** — ชี้ไป `--font-mono` ตอนเปิดโหมดนี้ |

🔑 **ต้องมี `--font-en` เป็นตัวกลางเสมอ** เพื่อให้สลับกลับไปใช้ Sarabun ล้วนได้ในที่เดียว
🚨 **โหมด "แบบปกติ" ต้องชี้ `--font-en` กลับไปที่ Sarabun ห้ามตั้งเป็นค่าว่าง**
ค่าว่างทำให้ประโยค `font-family` พังทั้งบรรทัด ตัวอักษรกลายเป็นฟอนต์ของระบบ

### ฟอนต์หัวเรื่องเฉพาะเว็บ — แยกต่างหาก ไม่บังคับ

แต่ละเว็บมีฟอนต์ของตัวเองสำหรับ **ชื่อเว็บ** ได้ ไม่ต้องเหมือนกัน

| เว็บ | ฟอนต์ชื่อเว็บ |
|---|---|
| มูลค่ายาคืน | **Krub** (พี่กันไล่ลองเอง 4 ตัว — Charm → Thasadith → Charmonman → Krub) |
| คลังคำ | Charmonman |

🚨 **ใช้กับชื่อเว็บเท่านั้น ห้ามลามไปที่อื่น** ฟอนต์ตกแต่งอ่านตัวเลขกับชื่อยายาก
ซึ่งเป็นข้อมูลความปลอดภัยที่ต้องอ่านง่ายที่สุด
⚠️ **ขนาดต้องใหญ่กว่าตัวพิมพ์ทั่วไป** เพราะเส้นบางกว่า

### 🔴🔴 เว็บที่มีอยู่แล้ว ห้ามแตะฟอนต์เอง ต้องรอพี่กันสั่ง

> พี่กันสั่ง 5 ก.ย. 2569: *"เว็บที่มีก่อนหน้าค่อย ๆ ปรับฟอนต์ **ไม่งั้นพังทั้งเว็บ**
>  ส่วนเว็บในอนาคตที่จะสร้าง ให้ใช้สองฟอนต์นี้เป็นฐานตั้งแต่เริ่มเลย"*

**เพราะ Roboto Mono กว้างกว่า Sarabun ราว 15%** เปลี่ยนทีเดียวทั้งเว็บแล้วของที่เคยพอดีจะล้นทุกจุด

เว็บยาคืนเคยเจอตอนเปลี่ยน — คอลัมน์วันที่ตกบรรทัดเป็นสองแถว · ตัวเลขใหญ่หน้าสรุปล้นออกนอกกรอบ ·
ชื่อผู้บันทึกถูกตัดท้ายด้วยจุดไข่ปลา · ต้องไล่แก้ทีละจุดทั้งเว็บ

| เมื่อไหร่ | ทำยังไง |
|---|---|
| **เว็บใหม่ที่กำลังจะสร้าง** | ✅ ใส่ทั้งสองฟอนต์ตั้งแต่วันแรก ใช้ท่าของ HCV |
| **เว็บที่มีอยู่แล้ว** | 🛑 **ห้ามแตะเอง** รอพี่กันสั่งแล้วค่อย ๆ ปรับทีละส่วน |

### ⚠️ กับดักที่เคยเจอจริง

**① ใบพิมพ์เอกสารราชการห้ามเปลี่ยนตาม**

ใบสรุปที่พิมพ์ส่งหน่วยงานอื่นต้องใช้ฟอนต์ราชการเสมอ ไม่ว่าคนใช้จะเลือกฟอนต์อะไรบนหน้าจอ
เว็บยาคืนปลอดภัยเพราะ `.slip-paper` เขียนชื่อฟอนต์ตรง ๆ ใน `@media print` ไม่ผ่านตัวแปลงกลาง

🚨 **แตะเรื่องฟอนต์เมื่อไหร่ ต้องสร้างไฟล์ PDF จริงแล้วคลายดูว่าฝังฟอนต์อะไรมา**

**②🔴 จุดที่เขียนชื่อฟอนต์ตรง ๆ จะไม่ถูกตัวแปลงกลางแตะ**

ตอนเว็บยาคืนเปลี่ยนฟอนต์ทั้งเว็บ **ชื่อยาทั้งเว็บไม่เปลี่ยนตามเลย**
เพราะไฟล์วาดชื่อยาเขียน `var(--font-sarabun)` ไว้เอง Sarabun เลยมาก่อนแล้วชนะ

**พี่กันจับได้เอง — แคลร์เปิดดูแล้วแต่ดูไม่ออกเพราะไม่ได้เทียบตัวอักษร**
🔑 **ต้องใส่ `var(--font-en)` ไว้หน้าสุดทุกจุดที่เขียนฟอนต์เอง**

**③ ปุ่มเลือกฟอนต์ในหน้าตั้งค่าต้องเขียนฟอนต์ตายตัว**

ไม่งั้นทั้งสองปุ่มจะเปลี่ยนตามที่เลือกอยู่ = เทียบกันไม่ได้

**④ จุด `.` ในคำไทยจะกว้างขึ้น**

`รพ.สต.` ดูเหมือน `รพ . สต .` เพราะจุดมีในฟอนต์ทั้งสองตัว เบราว์เซอร์เลยหยิบของ Roboto Mono มาใช้
พี่กันดูแล้วบอกว่าไม่ซีเรียส

## 6.9 🔴🔴🔴 ค่าที่ถูกใช้ข้ามหน้า ห้ามอยู่ในไฟล์ที่ถูกข้ามการคำนวณได้

**บั๊กที่ร้ายแรงที่สุดที่เว็บยาคืนเคยเจอ — บันทึกไม่ได้ทั้งเว็บ ติดอยู่หลายวัน**

### เรื่องที่เกิด

เว็บยาคืนทำให้เร็วขึ้นด้วยการ **ไม่คำนวณค่าของหน้าที่ยังไม่ได้เปิด** ซึ่งถูกต้องแล้ว

แต่มีตัวสั่งงานของปุ่มยืนยันตัวหนึ่ง (`confirmRun`) บังเอิญไปอยู่ในไฟล์ของหน้าประวัติ
**ทั้งที่หน้าบันทึกก็ใช้มันด้วย** — ป๊อปยืนยันเป็นของกลางที่ใช้ข้ามหน้า

```js
history: sc === 'history',                    // ❌ อยู่หน้าบันทึก = ไม่คำนวณ = ปุ่มตาย
history: sc === 'history' || !!stt.confirm,   // ✅ ของนั้นถูกใช้เมื่อไหร่ ต้องคำนวณด้วย
```

**อาการ** — ป๊อปยืนยันขึ้นครบสวยงาม กดปุ่ม "ยืนยันบันทึก" แล้ว **เงียบสนิท**
ไม่มีข้อความผิดพลาด ไม่มีอะไรในบันทึกของเบราว์เซอร์ ไม่มีคำขอออกไปหาเซิร์ฟเวอร์

พี่กันเจอเองตอนใช้งานจริง — *"เรากดส่งแล้วมันเด้งให้เลือกคนส่ง จากนั้นเรากดบันทึก มันไม่ไปเลย"*

### 🚨 ธงที่ใช้ตัดสินว่าจะคำนวณหน้าไหน ห้ามอยู่ในไฟล์ของหน้านั้นเอง

**วงจรอุบาทว์** — ไม่คำนวณหน้าราคา → ไม่มีธงที่บอกว่าอยู่หน้าราคา → กดเข้าหน้าราคาแล้วจอว่างถาวร

ธงพวกนี้ต้องอยู่ในไฟล์กลางที่คำนวณเสมอ **ไม่ใช่ในไฟล์ของหน้าที่มันคุม**

### 🔴 บทเรียนเรื่องการเทสที่แพงที่สุด

| วิธีเทส | จับบั๊กนี้ได้ไหม |
|---|---|
| ตั้งค่าในหน่วยความจำแล้วอ่านค่ากลับ | ❌ ผ่านหมด |
| เรียกฟังก์ชันบันทึกตรง ๆ | ❌ ผ่าน (ข้ามป๊อป) |
| **กดปุ่มจริงทีละขั้นเหมือนคนใช้** | ✅ **เจอ** |

⚠️ **สกิลเคยเขียนเตือนเรื่องนี้ไว้เองแล้ว** ว่า "ตรวจก่อนตัดทุกครั้งว่าไม่มีหน้าอื่นใช้ค่าข้ามไฟล์"
และเขียนว่าไล่ดูครบ 334 ค่าแล้ว **แต่พลาดตัวนี้ไป**
🔑 **การไล่ดูด้วยตาไม่พอ ต้องเทสเส้นทางจริงทุกเส้นหลังตัดการคำนวณ**

## 6.10 🔴🔴 แตะตาข่ายกันโค้ดแปลกปลอม ต้องเทสแบบเว็บจริงเสมอ

**บั๊กที่มีเฉพาะบนเว็บจริง หาสาเหตุยากที่สุด — อาการคือจอขาวทั้งใบ**

### ทำไมเทสในเครื่องไม่มีวันเจอ

ตอนรันในเครื่อง ตาข่ายนี้ถูกผ่อนให้หลวมกว่าปกติ เพราะเครื่องมือของนักพัฒนาต้องใช้
**เว็บจริงไม่มีการผ่อน** บั๊กจึงโผล่เฉพาะบนเว็บจริง

> *"เทสใน dev ผ่านหมด แต่พอ build เป็นเว็บจริงแล้ว **สคริปต์ถูกบล็อกทั้งหมด จอขาวทั้งใบ**"*

**ต้นเหตุ** — หน้าที่ระบบสร้างไว้ล่วงหน้าตอน build จะได้ไฟล์ก้อนเดิมที่ไม่มีใบอนุญาตติดมา
เบราว์เซอร์เลยบล็อกสคริปต์ทั้งหมด

**แก้ด้วยการบังคับให้ทุกหน้าสร้างสด** (`export const dynamic = 'force-dynamic'`)

🚨 **แตะเรื่องตาข่ายนี้เมื่อไหร่ ต้องสร้างเว็บแบบจริงแล้วเปิดดูเสมอ** ไม่ใช่เทสในเครื่องแล้วจบ

### 🚨🚨 ห้ามใช้ `eval()` หรือ `new Function()` เด็ดขาด

> *"ทั้งสองตัวรันโค้ดอะไรก็ได้ที่อยู่ในข้อความ และ **ตาข่ายของเว็บจริงบล็อกไว้อยู่แล้ว**
>  ตอนรันในเครื่องผ่อนให้ — **เว็บจริงจะพังเงียบ ๆ หาสาเหตุยากมาก**"*

เว็บยาคืนมีเครื่องคิดเลขในช่องจำนวน (พิมพ์ `25+25` แล้วได้ 50)
**เขียนตัวคิดเลขเองไล่อ่านทีละชั้น** แทนที่จะใช้ `eval()` ที่สั้นกว่ามาก

## 6.13 📐 กับดักการจัดวางกล่องแบบยืดหยุ่น — ครบชุด 5 ข้อ

### ① `margin:0 auto` + พ่อเป็นกล่องยืดหยุ่น = หน้าเว็บหดเงียบ ๆ

**เจอจริง เว็บยาคืนหดจาก 1360 เหลือ 1013 จุด** ไม่มีข้อความผิดพลาด ไม่มีคำเตือน
**แก้:** ใส่ `width:100%` ให้กล่องที่ใช้ `max-width` คู่กับ `margin:0 auto` ทุกตัวที่พ่อเป็นกล่องยืดหยุ่น

### ② กล่องลูกจะเลื่อนในตัวเองได้ พ่อทุกชั้นต้องมีความสูงที่แน่นอน

ชั้นไหนเป็น "ห้ามหด" จะทำให้ลูกไม่รู้ความสูงตัวเอง แล้วยืดตามเนื้อหาไปเรื่อย ๆ
**สูตร:** ทุกชั้นตั้งแต่พื้นที่เลื่อนลงมาต้องเป็น `flex:1;min-height:0`

### ③🚨 `flex:1` ย่อมาจาก `1 1 0%` — ฐานเป็นศูนย์ กล่องจึงไม่ยอมหด

**นี่คือกับดักที่ต่างจากข้อ ② และเจอแยกกัน**

```css
flex: 1;          /* = 1 1 0%  ฐานความสูงเป็นศูนย์ */
flex: 1 1 auto;   /* ✅ ฐานเป็นความสูงจริงของเนื้อหา */
```

**ฐานเป็นศูนย์ทำให้การคำนวณการหดได้ศูนย์ตาม กล่องไม่ยอมหดแม้ใส่ `min-height:0` แล้ว**
เว็บยาคืนเจอตอนกล่องในแผงขวาไม่ยอมหด **แล้วไปดันปุ่มบันทึกตกขอบแผง**

### ④ ของที่ "ยุบได้ตอนที่ว่างไม่พอ" ต้องเช็คว่ายุบแล้วยังอ่านได้

ใส่ให้กล่องเลื่อนในตัวเองได้ + ความสูงต่ำสุดน้อยเกินไป **= พอที่ว่างหด กล่องจะยุบจนเนื้อหาหายเข้าไปข้างใน**

🚨 **ซ่อนเนื้อหาในกล่องจิ๋ว แย่กว่าปล่อยให้ทั้งแผงเลื่อน**
ตั้งความสูงต่ำสุดที่อ่านได้จริง แล้วถ้าที่ไม่พอ ให้กลับไปเลื่อนทั้งหน้าแทน

**🔑 วิธีหาบั๊กนี้** — วัดพื้นที่เลื่อนทุกอันในหน้า แล้วหาตัวแปลกปลอม
กล่องที่ไม่ควรเลื่อนได้แต่เลื่อนได้ = ตัวที่ยุบ

### ⑤🔴 พื้นที่เลื่อนก้อนเดียวใช้ร่วมทุกหน้า = ตำแหน่งเลื่อนค้างข้ามหน้า

**พี่กันเจอเอง** — *"เราเลื่อนขึ้นลงในหน้าบันทึก ประวัติ แล้วพอเปิดหน้าอื่นมันค้างที่เดิม"*

เว็บที่สลับหน้าโดยไม่โหลดใหม่ ใช้พื้นที่เลื่อนก้อนเดียวกันทุกหน้า
**เปลี่ยนหน้าแล้วตำแหน่งเลื่อนไม่รีเซ็ต** — หน้าใหม่เปิดมาอยู่กลางหน้าแทนที่จะอยู่บนสุด

🚨 **ต้องรีเซ็ตตำแหน่งเลื่อนทุกครั้งที่เปลี่ยนหน้า** และแก้ทั้งฝั่งคอมกับมือถือ

## 6.14 🎭 สถานะที่หน้าตาเหมือนกันแต่คนละความหมาย — บั๊กที่เจอซ้ำที่สุด

**หลักการเดียวใช้ได้กับทุกคู่ — ต้องแยกด้วยธงต่างหาก ห้ามเดาจากผลลัพธ์**

| คู่ที่สับสนกัน | อาการที่เกิดจริง |
|---|---|
| **โหลดไม่สำเร็จ ↔ ไม่มีข้อมูล** | หน้าสรุปวาด ฿0.00 ทุกช่อง ซึ่งเป็นหน้าที่เอาไปเสนอผู้บริหาร |
| **ยังหาไม่เจอ ↔ เลือกไปแล้ว** | กดเลือกยาสำเร็จแล้ว แต่กล่อง "ไม่พบยาชื่อนี้" ยังค้างอยู่ |
| **โค้ดพัง ↔ ไม่มีอะไรให้เรียก** | ทั้งคู่เงียบเหมือนกัน **แต่แบบหลังเงียบที่สุด ไม่มีสัญญาณเตือนเลย** |

### ทำไมเดาจากผลลัพธ์ไม่ได้

```js
// ❌ ผิด — ผลว่างมีได้หลายความหมาย
if (results.length === 0) แสดง('ไม่พบ');

// ✅ ถูก — แยกด้วยธงต่างหาก
if (loadErr) แสดง('โหลดไม่สำเร็จ');
else if (picked) ไม่ต้องแสดงอะไร;          // เลือกไปแล้ว รายการปิดเป็นเรื่องปกติ
else if (q.length >= 2) แสดง('ไม่พบ');
```

### 🔴 แบบที่เงียบที่สุด — "โค้ดไม่ได้พัง มันแค่ไม่มีอะไรให้เรียก"

ตัวอย่างจริง — ปุ่มถูกวาดออกมาแต่ไม่มีฟังก์ชันผูก · ตัวสังเกตถูกติดตั้งแต่ไม่มีเป้าให้สังเกต ·
ฟังก์ชันถูกประกาศแต่ไม่มีใครเรียก

**ไม่มีข้อความผิดพลาด ไม่มีอะไรในบันทึกของเบราว์เซอร์ หน้าเว็บดูปกติทุกอย่าง**
🔑 **จับได้ทางเดียวคือกดใช้จริงทีละขั้นเหมือนคนใช้** หรือนับว่ามีกี่จุดที่เรียกใช้ของนั้น
