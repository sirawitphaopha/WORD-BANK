# ปุ่มต้องตอบสนอง — กฎกลาง ใช้ได้ทุกโปรเจกต์

> ตั้งขึ้น **27 สิงหาคม 2569** ตามที่พี่กันสั่ง: *"ใส่เรื่องปุ่มเปลี่ยนสี เป็นสกิลกลางด้วย"*
>
> ต้นเรื่องคือกฎที่พี่กันตั้งไว้ 26 ส.ค. 2569:
> *"เอาจริง ๆ นะ ทุกปุ่มควรเปลี่ยนสีตอนเอาเมาส์ไปชี้ ตั้งเป็นกฎการออกแบบ
>  เราขี้เกียจสั่งเธอให้ทำอันนี้แล้ว"*
>
> ทำเป็นสกิลกลางเพราะเว็บของพี่กันมีหลายตัว และเรื่องนี้พลาดซ้ำมาแล้วหลายรอบในเว็บเดียว

# 🔴 กฎ 8 ข้อ

## 1. ทุกปุ่มต้องเปลี่ยนตอนเอาเมาส์ชี้

ไม่มีข้อยกเว้น **นอกจากปุ่มที่พี่กันสั่งเองว่าไม่ต้อง**

รวมถึงปุ่มที่คนมักลืม:
- ปุ่มที่กดไม่ได้ (ต้องเปลี่ยน แต่เปลี่ยนแบบไม่ทำให้ดูเหมือนกดได้)
- หัวคอลัมน์ที่กดเรียงได้ (เป็นปุ่มชนิดหนึ่ง)
- ชื่อเว็บที่กดกลับหน้าแรกได้
- แถบเตือนที่กดปิดได้
- ฉากรับการกดนอกเมนู **ไม่ใช่ปุ่ม** ไม่ต้องมี

## 2. 🚨 ห้ามใช้กฎกลางครอบทุกปุ่ม

> *"อันนี้งานละเอียด ห้ามสร้างโค้ดแล้วให้ทุกปุ่มเปลี่ยน ต้องแก้มือทุกปุ่มเท่านั้น"*
> *"คิดทุก ๆ ปุ่ม ไม่เอาค่าตั้งต้น ต้องดูทีละปุ่มแล้ววิเคราะห์เท่านั้น"*

```css
/* ❌ ห้าม — ปุ่มพื้นขาวจะแทบไม่เปลี่ยน ปุ่มพื้นเข้มจะสว่างจนตัวหนังสือกลืน */
[role="button"]:hover { filter: brightness(.94); }
```

สีที่ถูกต้องขึ้นกับพื้นของปุ่มนั้น กฎกลางทำให้บางปุ่มดู**จางลง**แทนที่จะเด่นขึ้น

## 3. 🚨 สีตอนชี้ต้องอยู่ในโทนของปุ่มนั้น

> *"กรอบมันสีแดงนะ จุ้มไปต้องสีแดงสิ"*
> *"สีควรเข้ากับปุ่มนั้น ไม่ใช่ใส่แค่สีเทาเข้ม ต้องเข้ากับธีม"*

| ปุ่ม | ชี้แล้วต้องเป็น | ห้ามเป็น |
|---|---|---|
| ปุ่มลบ · ปุ่มทำลาย (แดง) | แดงเข้มขึ้น หรือพื้นแดงจาง | **เขียว** |
| ปุ่มบันทึก · ปุ่มยืนยัน (เขียว) | เขียวเข้มขึ้น | แดง · เทา |
| ปุ่มเตือน (ส้ม/อำพัน) | ส้มเข้มขึ้นในโทนเดิม | น้ำตาลเข้มจนดูคนละปุ่ม |
| ปุ่มพื้นขาว | สีจางของธีมหลัก + ขอบสีธีม | **เทากลาง** |

🚨 **ปุ่มที่ตอนปกติเป็นขาวหรือเทา ต้องตัดสินจากความหมายของปุ่ม ไม่ใช่จากสีพื้น**
ปุ่ม "ทำลาย" ที่พื้นใสตัวหนังสือเทา ก็ยังต้องชี้แล้วเป็นแดง

## 4. 🚨 ห้ามตั้งสีตอนชี้เป็นสีเดียวกับพื้นปุ่มเอง

```css
/* ❌ ปุ่มพื้น #e3f0e8 อยู่แล้ว ชี้แล้วไม่เปลี่ยนอะไรเลย */
.hv-bg-e3f:hover { background: #e3f0e8 !important; }
/* ✅ */
.hv-bg-e3f:hover { background: #cfe6da !important; }
```

เคยพลาดจนมีปุ่ม 24 จุดที่ชี้แล้วไม่มีอะไรเกิดขึ้น

**กฎเดียวกันใช้กับลิงก์** — ลิงก์สีเทล `#2f7d5d` ห้ามตั้งสีตอนชี้เป็น `#2f7d5d`

## 5. 🚨 ปุ่มที่พื้นเข้มอยู่แล้วไม่ต้องเข้มเพิ่มมาก

พี่กันสั่ง *"ปุ่มไหนที่เข้มอยู่แล้วไม่ควรเข้มเพิ่ม"*

ปุ่มพื้นเขียวทึบตัวหนังสือขาว ชี้แล้วเข้มขึ้นนิดเดียวพอ
เข้มมากจะกลายเป็นดำ ตัวหนังสือขาวยังอ่านได้แต่ปุ่มดูตาย

## 6. 🚨 อันที่ทำงานถูกอยู่แล้ว ห้ามไปแก้ให้แย่ลง

> *"อันไหนมันเปลี่ยนสีอยู่แล้วก็อย่าไปแก้ให้มันห่วยขึ้นสิวะ"*
> *"อันไหนดีแล้วก็เอาไว้นะ ไม่ใช่ถอนหมด เอาอันที่เธอเช็คแล้วมันแปลก"*

ก่อนแตะปุ่มไหน ต้องดูก่อนว่ามันเปลี่ยนสีอยู่แล้วหรือเปล่า

## 7. 🚨 ปุ่มที่เปลี่ยนสีตามสถานะ ต้องสลับคลาสตอนชี้ด้วย

```jsx
/* ❌ ตอนอยู่ในถังขยะปุ่มเป็นพื้นเขียวตัวหนังสือขาว
      ชี้แล้วพื้นกลายเป็นขาวนวล ตัวหนังสือขาวกลืนหายไป */
className="hv-bg-f6"
/* ✅ */
className={V.histTrash ? 'hv-teal' : 'hv-bg-f6'}
```

ตระกูลเดียวกับบั๊ก `border-color` เดี่ยวใน hover — เขียนครึ่งเดียวแล้วอีกครึ่งค้างของเก่า

🚨 **เขียน `border` เต็มประโยค ไม่ใช่ `border-color` เดี่ยว**
```css
/* ❌ ความหนากับชนิดเส้นค้างของเดิม กลายเป็นขอบดำหนา */
.x:hover { border-color: rgba(47,125,93,.34) !important; }
/* ✅ */
.x:hover { border: 1px solid rgba(47,125,93,.34) !important; }
```

## 8. 🚨 รายงานเรื่องสีต้องให้พี่กันเห็นของจริง

> *"เรามองเห็นสีเหรอ ตั้งกฎเลย เขียน code สีดีแล้ว แต่เอาสีให้เราเห็นด้วยยยย"*

**ห้ามส่งรหัสสีให้อ่าน** — `#dde0dc` พี่กันมองไม่ออกว่าคือสีอะไร

ใช้อย่างใดอย่างหนึ่ง:
- **มอคอัป HTML ให้กดดู** (ดีที่สุดสำหรับแอนิเมชัน เพราะภาพนิ่งดูไม่ได้)
- **ภาพถ่ายหน้าจอจริง** ทั้งก่อนชี้และตอนชี้
- **เรียกชื่อสีเป็นภาษาคน** — เขียวอ่อน · แดงจาง · ครีมอมเหลือง

# 🎨 เลือกสีตอนชี้ยังไง

| พื้นปุ่มตอนปกติ | ตอนชี้ | ตัวอย่าง (ธีมเขียว) |
|---|---|---|
| สีทึบเข้ม | เข้มขึ้น 15-20% ในโทนเดิม | `#2f7d5d` → `#24614a` |
| สีอ่อนของธีม | เข้มขึ้นในโทนเดิม | `#e3f0e8` → `#cfe6da` |
| ขาว มีขอบ | พื้นสีจางของธีม + ขอบเข้มขึ้น + ตัวหนังสือสีธีม | ขาว → `#e8f2ec` |
| ใส ไม่มีขอบ | พื้นจางบาง ๆ + ตัวหนังสือสีธีม · **ห้ามใส่ขอบ** (ขอบดันตัวหนังสือขยับ) | ใส → `#eef4f0` |
| แดง (ลบ/ทำลาย) | แดงเข้มขึ้น หรือพื้นแดงจาง + ตัวหนังสือแดงอิฐ | `#fdf1ed` + `#c2543c` |

**วิธีหาสีเข้มขึ้นที่อยู่ในโทนเดิม** — ลดความสว่างลง อย่าเปลี่ยนเฉดสี
เฉดสี (hue) ต้องอยู่ในช่วง ±40 องศาบนวงล้อสีเสมอ ถ้าเกินนั้นคือคนละโทนแล้ว

# 🚫 ปุ่มที่กดไม่ได้

**ต้องเปลี่ยนตอนชี้เหมือนกัน** แต่เปลี่ยนแบบที่ยังอ่านว่า "กดไม่ได้"

| ทำ | ไม่ทำ |
|---|---|
| เข้มขึ้นแค่พอรู้ว่าเมาส์อยู่ตรงนี้ | เข้มจนดูเหมือนกดได้ |
| ใช้สีที่บอกสถานะ (อำพัน = รอ) | ใช้สีเขียวของปุ่มที่กดได้ |
| ใช้สีของปุ่มตัวเองที่จางลง (เขียว→เขียวจาง) | ยกสีจากปุ่มอื่นมาใช้ |
| แอนิเมชัน **เฉพาะปุ่มที่พี่กันสั่งเอง** | ใส่แอนิเมชันเองเพราะเห็นว่าคล้ายปุ่มอื่น |

🚨 **สีเทาไม่ใช่คำตอบเดียว** พี่กันบอกตรง ๆ ว่า *"ไม่ชอบสีเทา"*
ปุ่มที่รออะไรบางอย่างใช้**ครีมอมเหลือง/อำพัน**ได้ ซึ่งบอกสถานะ "ยังไม่พร้อม" ชัดกว่าเทา

**ตัวอย่างที่ใช้จริง** — ปุ่มบันทึกตอนยังไม่เลือกยา
```css
.hv-wait { transition: background-color .15s ease, color .15s ease, border-color .15s ease }
.hv-wait:hover {
  background: #f4e3bc !important; color: #96650f !important;
  border-color: rgba(150,101,15,.45) !important;
  animation: hv-shake .42s ease;
}
@keyframes hv-shake {
  0%,100% { transform: translateX(0) }
  18% { transform: translateX(-5px) }  36% { transform: translateX(5px) }
  54% { transform: translateX(-3px) }  72% { transform: translateX(3px) }
  86% { transform: translateX(-1px) }
}
```

# ✨ แอนิเมชัน

## 🚨🔴 ใส่แอนิเมชันได้เฉพาะปุ่มที่พี่กันสั่งเองเท่านั้น

**พี่กันสั่ง 27 ส.ค. 2569: *"ปุ่มไหนอนิเมชั่น เราบอกเอง"***

ห้ามคิดเองว่าปุ่มนี้ควรมี · ห้ามยกชุดจากปุ่มที่พี่กันสั่งไปใส่ปุ่มอื่นที่ดูคล้ายกัน
แม้จะเป็นปุ่มที่ทำหน้าที่คล้ายกันแค่ไหนก็ตาม

**บทเรียน 27 ส.ค. 2569** — พี่กันสั่งแอนิเมชันสั่นให้ปุ่มบันทึกตอนยังไม่เลือกยา
แคลร์เห็นว่าปุ่ม "เพิ่ม" ก็เป็นปุ่มที่กดไม่ได้เหมือนกัน เลยยกชุดครีมอมเหลือง + สั่นไปใส่ด้วย
โดยอ้างกฎ "อะไรที่คล้ายกันต้องทำให้เหมือนกัน" — **พี่กันสั่งเอาออกทันที**

> *"ปุ่มเพิ่ม ไม่เอาอนิเมชั่น ไม่ได้บอก แล้วปุ่มมันจริง ๆ สีเขียว ก็แค่เปลี่ยนสีเขียวปกติ"*

**สองบทเรียนในประโยคเดียว**
1. แอนิเมชันไม่ใช่ของที่ลามไปเองได้ ต้องได้รับคำสั่งรายปุ่ม
2. **ปุ่มที่กดไม่ได้ ต้องใช้สีของปุ่มตัวเองที่จางลง** ไม่ใช่ยกสีจากปุ่มอื่นมา
   ปุ่มเขียว → เขียวจาง · ปุ่มแดง → แดงจาง · ไม่ใช่ครีมของปุ่มที่พี่กันสั่งไว้อีกตัว

## ใช้เมื่อไหร่

| ใช้ | ไม่ใช้ |
|---|---|
| **พี่กันสั่งปุ่มนั้นตรง ๆ** | **ทุกกรณีที่พี่กันไม่ได้สั่ง** |
| | ปุ่มที่ดูคล้ายกับปุ่มที่พี่กันเคยสั่ง |
| | ปุ่มที่กดบ่อยทุกวัน (น่ารำคาญ) |

## กฎ 4 ข้อ (เมื่อได้รับคำสั่งแล้ว)

1. 🚨 **ต้องจางหายเมื่อจบ ห้ามค้าง** — ชั้นที่ค้างอยู่ก็คือการเปลี่ยนสีถาวรนั่นเอง
   ถ้าปุ่มนั้นถูกสั่งว่า "ห้ามเปลี่ยนสี" การใส่ `forwards` เท่ากับละเมิดคำสั่ง
2. 🚨 **ต้องมี `@media (prefers-reduced-motion: reduce)` เสมอ**
   เจ้าหน้าที่บางคนเวียนหัวกับภาพเคลื่อนไหว
3. 🚨 **ห้ามบังตัวหนังสือ** — ชั้นซ้อนต้องจางพอที่ยังอ่านออก
   หรือใส่ `z-index` ให้เนื้อหาอยู่บน (`.x > * { position: relative; z-index: 1 }`)
4. 🚨 **ทำด้วยชั้นซ้อน `::before` / `::after` ไม่แตะสีจริงของปุ่ม**
   ต้องใส่ `position: relative` กับ `overflow: hidden` ที่ตัวปุ่มด้วย

## ตัวอย่างที่ผ่านการเคาะแล้ว

**ปุ่มธีม "สว่าง" — แสงอุ่นเปล่งจากกลางปุ่ม**
```css
.hv-sun { position: relative; overflow: hidden }
.hv-sun::after {
  content: ""; position: absolute; inset: 0; pointer-events: none; border-radius: inherit;
  background: radial-gradient(circle at 50% 52%, rgba(255,196,72,.62), rgba(255,196,72,.16) 46%, transparent 68%);
  opacity: 0; transform: scale(.3);
}
.hv-sun:hover::after { animation: hv-sunrise 1.05s cubic-bezier(.22,.68,.32,1) }
@keyframes hv-sunrise {
  0% { opacity:0; transform:scale(.3) }   38% { opacity:1; transform:scale(1.06) }
  62% { opacity:1; transform:scale(1) }   100% { opacity:0; transform:scale(1) }
}
```

**ปุ่มธีม "เข้ม" — ผืนมืดคืบมาจากขวา แล้วมีดาวขึ้น**
```css
.hv-moon::after {
  content: ""; position: absolute; inset: 0; pointer-events: none; border-radius: inherit;
```

## `hover-check.mjs` — เปลี่ยนไหม

🚨 **ต้องอ่านค่าสีที่เบราว์เซอร์คำนวณ ห้ามเทียบภาพ**

รุ่นแรกถ่ายภาพปุ่มก่อน/หลังชี้มาเทียบไบต์ต่อไบต์ โดยรอแค่ **0.045** กับ **0.16 วินาที**
ทั้งที่การไล่สีใช้เวลา **0.12–0.15 วินาที** ภาพจึงถ่ายติดตอนสียังไหลไม่ถึงที่

ผลคือ**รายงานไม่ตรงกันทุกรอบที่รัน** — รอบหนึ่งฟ้องปุ่มกลับ อีกรอบฟ้องชิปแหล่งที่มา
พอตรวจทีละปุ่มด้วยมือแล้วทุกตัวเปลี่ยนสีจริงหมด

**ตัวตรวจที่รายงานผิดแย่กว่าไม่มีตัวตรวจ** — ให้ความมั่นใจแบบผิด ๆ แล้วไล่หาสาเหตุผิดทาง

```js
const paint = () => page.evaluate((xy) => {
  const el = document.elementFromPoint(xy[0], xy[1]);
  const hit = el.closest('[role="button"], button') || el;
  const g = getComputedStyle(hit);
  return g.backgroundColor + '|' + g.color + '|' + g.borderColor + '|' + g.opacity;
}, [sp.x, sp.y]);

await page.mouse.move(5, 5);      await wait(420);  const before = await paint();
await page.mouse.move(sp.x, sp.y); await wait(620);  const after  = await paint();
if (before && before === after) dead.push(sp.label);
```

## `hue-check.mjs` — ถูกโทนไหม

ตัวแรกเช็คได้แค่ "เปลี่ยนไหม" — **ปุ่มแดงที่ชี้แล้วเป็นเขียวก็ผ่าน** เพราะสีเปลี่ยนจริง

ตัวนี้เทียบ**เฉดสีบนวงล้อ** ต่างเกิน 40 องศา = คนละโทน
รายงานเป็น**ชื่อสีภาษาไทย** (แดง · ส้ม · เขียว · ม่วง) ไม่ใช่รหัสสี

🚨 **มีจุดบอดที่ตัดสินแทนคนไม่ได้** — ปุ่มที่ตอนปกติเป็นขาวหรือเทาไม่มีโทนให้เทียบ
จึงแยกออกมาเป็นรายการ **"ต้องอ่านเอง"** แทนที่จะเดา
ต้องตัดสินจาก**ความหมายของปุ่ม** (ทำลาย=แดง · บันทึก=เขียว · รอ=อำพัน)

**นี่คือจุดที่ปุ่มทำลายรอดสายตามาได้** ทั้งที่รันตัวตรวจครบทั้งสองตัว

# 🧰 กับดักเทคนิคที่เจอบ่อย

🚨 **สไตล์ที่ฝังในแท็กชนะกฎ CSS เสมอ** — ต้องใส่ `!important` และ**วัดค่าจริงในเบราว์เซอร์**
ว่าใช้ผลได้จริงหรือเปล่า อย่าเชื่อแค่ว่าเขียนกฎถูกแล้ว

🚨 **คอมเมนต์ CSS ที่ปิดเกินหนึ่งตัว ฆ่ากฎทุกข้อที่เหลือในไฟล์**
แก้กี่รอบเว็บก็ไม่เปลี่ยน แล้วจะไล่หาสาเหตุผิดทางไปเรื่อย
**ตรวจด้วยการนับ** — จำนวน `/*` ต้องเท่ากับ `*/` เป๊ะ

```bash
node -e "const s=require('fs').readFileSync('app/globals.css','utf8');
console.log((s.match(/\/\*/g)||[]).length, (s.match(/\*\//g)||[]).length)"
```

🚨 **เปลี่ยน `display` เป็น `flex` ทำให้ `text-align` ไม่มีผลทันที**
ตัวเลขที่เคยกึ่งกลาง/ชิดขวาไหลไปชิดซ้ายหมด **โดยไม่มี error อะไรเลย**
ต้องเพิ่ม `justify-content` คู่กับ `text-align` เดิมทุกช่องที่ไม่ได้ชิดซ้าย

🚨 **คอมเมนต์ JSX `{/* */}` วางได้เฉพาะตำแหน่งที่รับ element**
วางในแอตทริบิวต์ของแท็ก · หลัง `) : (` · ในบล็อก `.map()` ที่คืนค่าเดียว = เว็บพังทันที
ถ้าจะเขียนคำอธิบายตรงนั้น ใช้คอมเมนต์จาวาสคริปต์ `//` เหนือบรรทัดแทน
