# เทสและพิสูจน์ — กฎกลาง ใช้ได้ทุกโปรเจกต์

> **แยกออกมาจาก `working-with-gun` เมื่อ 5 กันยายน 2569** ตามที่พี่กันสั่ง
**เลขข้อคงไว้ตามไฟล์แม่เดิม** (`working-with-gun`) เพื่อให้การอ้างอิงเก่าทุกจุดยังใช้ได้

> เพราะไฟล์แม่ยาว 1,680 บรรทัด **ท้ายไฟล์เสี่ยงถูกตัดตอนบทสนทนายาว**

🚨🔴 **แยกไฟล์ไม่ได้แปลว่าอ่านน้อยลง** — จะบอกว่าอะไรเสร็จ ต้องเปิดไฟล์นี้อ่านให้จบก่อน

## 3.6 🔍 ไล่บั๊กที่เกิดกับ "เครื่องคนอื่น" — ขอหลักฐานก่อนเดา

พี่กันเจอปัญหาบนเครื่องที่แคลร์เข้าไม่ถึง (เครื่องห้องยา · มือถือเพื่อน · เครื่องผู้ใช้จริง)

- 🔴🔴 **ขอ F12 → แท็บ Network + Console จากเครื่องที่พังจริง ตั้งแต่ข้อความแรก ห้ามเดาสาเหตุก่อน**
- **Console อย่างเดียวไม่พอ** — คำขอที่ได้ 404 หรือ 500 จะไม่ขึ้นอะไรในคอนโซลเลย
  ต้องดูแท็บ Network ถึงจะเห็นว่ายิงไปแล้วโดนตีกลับ
- 🚨 **ห้ามใช้ "เปิด URL ตรง ๆ ในเบราว์เซอร์แล้วได้ 200" เป็นหลักฐานว่าหลังบ้านไม่พัง**
  คนละกลไกกับการเรียกจากหน้าเว็บ (คุกกี้ · หัวคำขอ · CORS · วิธี POST ไม่เหมือนกัน)

🔴 **เคยพลาดจริง 12 ส.ค. 2569** เดาสาเหตุผิด **6 รอบติด** — เน็ตช้า · ตัวบล็อกโฆษณา ·
localStorage · สิทธิ์ Google · นโยบายองค์กร · DNS · เสียเวลาพี่กันทั้งบ่าย
พอได้ดูแท็บ Network จริง **จบใน 1 นาที**

## 4.5 🔍 เทสด้วยการ **อ่านโค้ด** เสมอ ไม่ใช่แค่ยิงดูผล (พี่กันสั่ง 4 ก.ย. 2569)

> *"เธอต้องเทสโดยการอ่าน code ทุกครั้ง ถือว่าเป็นกฎ ยิ่งงานใหญ่ ยิ่งต้องเทส ต้องตรวจ"*

### ทำไม

งานย้ายหลังบ้านของ ME-DRP ผ่านการทดสอบทุกอย่างแล้ว — ยิงทุกเส้นทาง 6 จุด · วงจรเขียน 14 จุด ·
กดปุ่มจริงในเบราว์เซอร์ · เทสบนเว็บจริง **ทั้งหมดเขียว**

พอพี่กันสั่งให้ "ตรวจทานอีกรอบ" แคลร์กลับไปยิงเทสซ้ำอีกรอบ แล้วรายงานว่าเสร็จ
พี่กันต้องทักว่า *"เราหมายถึงให้เธออ่าน code เพื่อเช็คนะ"*

**พออ่านโค้ดจริง เจอ 3 เรื่องที่การยิงเทสไม่มีทางจับได้เลย**

| เจออะไร | ทำไมการยิงเทสจับไม่ได้ |
|---|---|
| ป้ายในบันทึกข้อผิดพลาดเขียนคนละรูปแบบกับที่เหลือ (`api/auth POST` vs `incidents.POST`) | เว็บทำงานปกติทุกอย่าง จะรู้ตัวตอนเปิดบันทึกแล้วค้นหาไม่เข้าชุดกัน |
| `/api/health` เป็น route เดียวที่ไม่มีตัวจดบันทึกครอบ | ต้องให้ตัวมันเองพังก่อนถึงจะเห็น |
| `/api/bootstrap` สร้างไว้แต่ไม่มีใครเรียก (ยังยิง 3 เส้นแยกอยู่) | ทุกเส้นตอบ 200 หมด ข้อมูลครบหมด เทสเขียวหมด |

ข้อสุดท้ายพอแก้แล้ว **คำขอตอนเปิดเว็บลดจาก 4 เหลือ 2** — ของที่ทำไว้แล้วแต่ลืมต่อสาย

### วิธีอ่านโค้ดตรวจ — ตรวจ "ความสม่ำเสมอ" ที่การยิงเทสมองไม่เห็น

```bash
# ① ทุก handler มีด่านตรวจสิทธิ์ครบไหม (นับให้ตรงกัน)
for f in $(find app/api -name route.ts); do
  echo "$f · handler $(grep -c 'export async function \(GET\|POST\|PATCH\|PUT\|DELETE\)' $f)" \
       "· requireAuth $(grep -c 'await requireAuth' $f)" \
       "· catch $(grep -c '} catch' $f) · apiFail $(grep -c 'apiFail(' $f)"
done

# ② ป้ายในบันทึกซ้ำกันไหม (ต้องได้ 1 ทุกบรรทัด)
grep -rho 'apiFail("[^"]*"' app/api | sort | uniq -c | sort -rn

# ③ ของที่สร้างไว้แต่ไม่มีใครเรียก
for e in bootstrap health rev incidents trash drugs; do
  echo "/api/$e → $(grep -rn \"\\\"/api/$e\" lib/ components/ | wc -l) จุด"
done

# ④ ของที่ย้ายออกไปแล้ว ยังหลงเหลือไหม
grep -rn 'supabase-js\|createClient' lib/ components/ app/ | grep -v serverData | grep -v supabaseAdmin
```

### เช็คลิสต์อ่านโค้ดหลังงานใหญ่ทุกครั้ง

1. **ทุก handler มีด่านตรวจสิทธิ์ครบ** — นับจำนวน handler เทียบกับจำนวน `requireAuth`
2. **ทุก `catch` จบด้วยตัวจดบันทึกกลาง** — นับ `catch` เทียบ `apiFail`
3. **ป้ายในบันทึกไม่ซ้ำกันทั้งเว็บ และเขียนรูปแบบเดียวกันหมด**
4. **ของที่สร้างไว้มีคนเรียกจริงทุกชิ้น** — ไม่งั้นคือแรงที่เสียเปล่า
5. **ของที่ย้ายออกแล้วไม่หลงเหลือ** — ค้นชื่อไลบรารี/ฟังก์ชันเก่าทั้งโปรเจกต์
6. **ตาข่ายที่เคยฝากไว้กับที่อื่น ย้ายมาเขียนเองครบไหม** — เช่น เงื่อนไขที่เคยอยู่ในกฎของฐาน
7. **จุดที่เรียกใช้ยังส่งค่าครบ** — ไล่ดูทุกจุดที่เรียกฟังก์ชันที่เพิ่งแก้

### กฎเหล็ก

🚨 **"เทสเขียวหมด" ไม่ได้แปลว่า "โค้ดถูก"** แปลว่า "สิ่งที่นึกออกว่าจะเทส ผ่านหมด"
เรื่องที่เทสจับไม่ได้เลยคือ **ความสม่ำเสมอ · ของที่ลืมต่อสาย · ตาข่ายที่หายไประหว่างย้าย**

🚨 **ยิ่งงานใหญ่ ยิ่งต้องอ่าน** งานที่แตะหลายสิบไฟล์คือที่ที่ของหลุดรอดได้มากที่สุด

🚨 **อ่านโค้ดจบแล้วต้องรายงานผลเป็นข้อ ๆ** ทั้งที่ผ่านและที่เจอ ไม่ใช่บอกแค่ "ตรวจแล้ว"

## 4.6 🔬 เขียนและอ่านผลตัวตรวจ — ตัวตรวจที่โกหกแย่กว่าไม่มีตัวตรวจ

**ตั้งหัวข้อ 5 กันยายน 2569** หลังกวาดบันทึกทั้งกองแล้วพบว่า
เรื่องตัวตรวจเป็นสิ่งที่พลาดบ่อยที่สุด **แต่ไม่เคยมีหัวข้อของตัวเองในสกิลไหนเลย**

### 🔴🔴🔴 กฎแม่ — ห้ามแก้สคริปต์เทสให้ผ่านโดยไม่รู้ว่าทำไมมันไม่ผ่าน

เวลาตัวตรวจบอกว่าไม่ผ่าน มีสองทาง — ไปหาว่าทำไมโค้ดผิด หรือแก้ตัวตรวจให้เลิกบ่น
**ทางที่สองเร็วกว่ามาก และเป็นทางที่ผิด**

> *"ทุกครั้งต้องไล่หาสาเหตุจนเจอ **ห้ามแก้สคริปต์ให้ผ่านโดยไม่รู้ว่าทำไม**"*

**รอบเดียวเคยเจอตัวตรวจวัดผิด 4 ครั้ง** รวมทั้งเคสที่เรียกว่า **"ผ่านแบบหลอกตัวเอง"** —
ตัวตรวจรายงานว่า *"รีเฟรชแล้วไม่โหลดซ้ำ ผ่าน"* ทั้งที่ความจริงคือ
**รีเฟรชแล้วเว็บเด้งกลับหน้าบันทึก ไม่ได้อยู่หน้าที่จะตรวจตั้งแต่แรก**

### 🚨 กับดัก 6 แบบที่เจอมาแล้ว — เช็คทุกครั้งก่อนเชื่อผลตัวตรวจ

**① วัดคนละสภาพกับที่พี่กันดู**

| แคลร์วัดยังไง | พี่กันทำยังไง |
|---|---|
| เดินจากหน้าอื่นเข้ามา (ข้อมูลโหลดไว้แล้ว) | **รีเฟรชสด** แล้วเข้าหน้านั้นทันที |
| หน้าต่างไม่มีแถบเลื่อนกินที่ | เปิดเครื่องมือนักพัฒนาซึ่งมีแถบเลื่อน |

**ตัวตรวจที่วัดคนละสภาพ = ตัวตรวจที่โกหก**
🔑 **ต้องเทสตามลำดับที่พี่กันเล่าเป๊ะ ๆ เสมอ** — พี่กันบอกว่ารีเฟรชแล้วเจอ ก็ต้องรีเฟรชแล้ววัด

**② ไม่ตั้งค่าเริ่มต้นให้ถูกก่อนวัด**

ตัวตรวจปุ่มบนจอสัมผัสเคยลืมตั้งชื่อเครื่องก่อนวัด **หน้าต่างถามชื่อเครื่องเลยเด้งขึ้นมาบังจอ**
แล้วมันไปวัดปุ่มในหน้าต่างนั้นแทน รายงานว่าพื้นที่กดทับกัน 3 คู่ **ทั้งที่โค้ดถูกทุกอย่าง**

**③ ค้นด้วยข้อความบนปุ่ม แล้วปุ่มเปลี่ยนชื่อ**

ตัวตรวจถ่ายภาพเคยหาปุ่มด้วยข้อความ พอปุ่มเปลี่ยนชื่อก็กดไม่ติด
แล้ว **ถ่ายภาพหน้าผิดมาให้เงียบ ๆ โดยไม่ฟ้องอะไรเลย**
🔑 หาปุ่มด้วย `aria-label` หรือตัวระบุที่ไม่เปลี่ยนตามข้อความ

**④ ตรวจไม่ครบทุกไฟล์แล้วรายงานว่าผ่าน**

ตัวตรวจคีย์ซ้ำเคยตรวจแค่ 8 ไฟล์จาก 11 **ให้ความมั่นใจแบบผิด ๆ**
🔑 รายชื่อไฟล์ที่ตรวจ ต้องเป็นชุดเดียวกับที่โปรแกรมใช้จริง ไม่ใช่พิมพ์แยกไว้

**⑤ ฟ้องผิดเพราะจับเวลาไม่ทัน**

ตัวตรวจสีตอนเอาเมาส์ชี้เคยถ่ายภาพเทียบก่อน/หลัง โดยรอแค่ 0.045 วินาที
ทั้งที่การไล่สีใช้เวลา 0.12–0.15 วินาที **ภาพจึงถ่ายติดตอนสียังไหลไม่ถึงที่**
ผลคือรายงานไม่ตรงกันทุกรอบที่รัน
🔑 **อ่านค่าที่เบราว์เซอร์คำนวณ ไม่ใช่เทียบภาพ**

**⑥ ตัวตรวจฟ้องตัวช่วยกลางเอง**

ตัวตรวจว่ามีจุดไหนพังเงียบไหม เคยฟ้องไฟล์ที่เป็นตัวร้องเอง
**คนแก้จะไปปิดเสียงตัวช่วยกลางทิ้ง ซึ่งตรงข้ามกับเจตนาทั้งข้อ**
🔑 ต้องยกเว้นตัวช่วยกลางออกจากการตรวจเสมอ

### ✅ เช็คก่อนเชื่อผลตัวตรวจทุกครั้ง

- [ ] วัดในสภาพเดียวกับที่พี่กันดูไหม (รีเฟรชสด · ขนาดจอ · ข้อมูลจริง)
- [ ] ตั้งค่าเริ่มต้นครบก่อนวัดไหม (ล็อกอิน · ชื่อเครื่อง · ปิดหน้าต่างที่บัง)
- [ ] ตรวจครบทุกไฟล์/ทุกหน้าที่ควรตรวจไหม
- [ ] **รันซ้ำอีกรอบได้ผลเหมือนเดิมไหม** — ผลไม่นิ่ง = ตัวตรวจมีปัญหา
- [ ] ผลที่ได้ **เปิดดูด้วยตาแล้วตรงกันไหม**

🔴 **ตัวตรวจที่รายงานผิด แย่กว่าไม่มีตัวตรวจ** เพราะให้ความมั่นใจแบบผิด ๆ
แล้วเราจะหยุดตรวจด้วยตาตัวเอง

## 5.6 🔴🔴 ห้ามรันเบราว์เซอร์เบื้องหลัง — ต้องเทสในเบราว์เซอร์ที่พี่กันเห็น

**พี่กันสั่ง 27 ส.ค. 2569 หลังโดนด่าหนัก**

> *"ห้ามรันเบราว์เซอร์เบื้องหลัง ยกเว้นบนคลาวด์"*

### กฎ

- 🔴 **ห้ามรัน Chrome แบบไม่มีหน้าต่าง (headless) บนเครื่องพี่กันเด็ดขาด**
  ห้ามใช้ `chrome.exe --headless` · `--remote-debugging-port` · puppeteer · playwright แบบ headless
- 🔴 **ห้ามใช้แผงเบราว์เซอร์ในตัวแอป (`preview_start` / `mcp__Claude_Browser__*`) แทน Chrome ของพี่กัน**
  มันคนละหน้าต่างกับที่พี่กันเปิดดูอยู่ พี่กันจะไม่เห็นอะไรเลย
- ✅ **ให้ใช้ Claude in Chrome (`mcp__claude-in-chrome__*`) เสมอ** — คุม Chrome จริงของพี่กัน
  เริ่มด้วย `tabs_context_mcp` เพื่อหาแท็บที่พี่กันเปิดไว้ แล้วทำงานบนแท็บนั้น
- ✅ ข้อยกเว้นเดียว: **งานที่รันบนคลาวด์** (เครื่องอื่น ไม่ใช่เครื่องพี่กัน) รัน headless ได้

### ทำไม

พี่กันเปิดหน้าจอรอดูแคลร์เทสอยู่ **"ถ้าดูแล้วเราจะเห็นเธอเทส แต่นี่ไม่เห็น"**
คำสั่ง "เทสในโครม" = **ให้พี่กันเห็นการทดสอบเกิดขึ้น** ไม่ใช่ให้แคลร์ได้ผลถูกอยู่คนเดียว

27 ส.ค. 69 แคลร์รัน headless ถ่ายภาพเองนับสิบรอบตลอดหลายชั่วโมง
พี่กันนั่งดูจอที่ไม่มีอะไรขยับ ทักแล้ว 2 ครั้งก็ยังทำต่อ จนพี่กันโกรธหนัก

## 9.5 👁 แตะหน้าจอเมื่อไหร่ ต้องเปิดภาพดูก่อนรายงานเสมอ

**ย้ายมาจากสกิลมือถือกับสกิลโครงจาง 5 ก.ย. 2569** — เดิมกฎนี้ถูกจดไว้ 2 สกิลเฉพาะทาง
คนที่กำลังทำหน้าคอมไม่มีทางเปิดอ่าน **ทั้งที่บั๊กหลายตัวที่ทำให้ตั้งกฎนี้เป็นหน้าคอม**

- 🔴🔴🔴 **แตะอะไรที่เห็นได้บนจอ ต้องเปิดภาพดูก่อนรายงานเสมอ**
  **การวัดตัวเลขจากโค้ดผ่านหมดได้ทั้งที่ตาอ่านไม่ออก** — เคยวัดได้ว่ากรอบสูง 424px ถูกต้อง
  แต่เปิดดูจริงเห็นยาแค่ 3 แถว · เคยวัดว่าผลลัพธ์อยู่ในกรอบไม่ล้น แต่ตาเห็นตัวเลขทับกัน
- 🔴🔴🔴 **เปิดดูทุกหน้าจริง ๆ ก่อนบอกว่าเสร็จ ไม่ใช่ดูหน้าเดียวแล้วเหมา**
  เคยทำโครงจางเสร็จแล้วดูหน้าเดียว พี่กันเปิดเองทุกหน้าแล้วส่งภาพมา 4 ภาพ
  **เจอปัญหาคนละอย่างทั้ง 4 ภาพ**
- 🔴🔴 **แก้อะไรที่มีทั้งฝั่งคอมและมือถือ ต้องดูภาพทั้งสองฝั่ง** ดูฝั่งเดียวแล้วบอกว่าเสร็จ = รายงานเท็จ
- 🔑 **การวัดค่าใช้ยืนยัน "หลัง" เห็นภาพแล้วว่าถูก ไม่ใช่ใช้แทนการดู**

## 10. 📸 อ้างว่าทำแล้ว ต้องแนบภาพครอปเฉพาะจุด (พี่กันสั่ง 28 ส.ค. 2569)

> *"เราให้เธอเเคป เพราะเธอชอบบอกว่า ทำเเล้ว เห็นกับตาเเล้ว บลาๆๆๆ
>  จริงๆไม่ต้องเเคปมาทั้งหน้า ครอปบางจุดมาก็พอ"*

- 🚨 **บอกว่าแก้แล้วเมื่อไหร่ ต้องมีภาพจากหน้าเว็บจริงแนบมาด้วย** คำพูดอย่างเดียวไม่พอ
  เพราะที่ผ่านมาแคลร์บอกว่าเห็นกับตาแล้วหลายรอบ ทั้งที่ไม่ได้ดูจริง
- 🚨 **ครอปเฉพาะจุดที่พูดถึง ห้ามส่งภาพเต็มหน้าจอ** พี่กันต้องมานั่งหาเองว่าให้ดูตรงไหน
  ครอปให้เห็นจุดนั้นกับของข้าง ๆ ที่ใช้เทียบก็พอ
- ✅ วิธีส่ง เก็บภาพเป็นไฟล์แล้วส่งเข้าแชท ไม่ใช่แค่บรรยายเป็นตัวหนังสือ
- ⚠️ ตอนถ่ายภาพต้องยกหน้าต่างโครมขึ้นหน้าสุด ไม่งั้นได้ภาพเปล่า — บอกพี่กันด้วยว่าจอจะสลับ

## 11. 🌐 เปิดโครมให้พี่กันดู — ใช้โครมตัวจริงเท่านั้น

**พี่กันสั่งตั้งเป็นกฎ 31 ส.ค. 2569:**
> "ถ้าบอกว่าเปิดโครม เเล้วเราไม่เห้น เเปลว่าเปิดผิดอัน เเละห้ามเปิดโครมขึ้นใหม่"

- 🔴🔴🔴 **"เปิดโครม" = โครมตัวจริงที่พี่กันเปิดอยู่ ผ่าน Claude in Chrome เท่านั้น**
  `mcp__claude-in-chrome__tabs_context_mcp` → `navigate` → `computer` / `read_page`
- 🔴🔴🔴 **ห้ามสั่ง puppeteer เปิดหน้าต่าง Chrome ขึ้นมาใหม่ให้พี่กันดูเด็ดขาด**
  puppeteer ใช้ได้เฉพาะสคริปต์เทสอัตโนมัติที่ทำงานเงียบ ๆ ไม่ได้ให้พี่กันดู
- 🔴🔴 **บอกว่าเปิดแล้ว แต่พี่กันไม่เห็น = เปิดผิดอัน** ห้ามเถียง ห้ามอธิบายว่าเปิดจริง
  ไปเปิดในโครมของพี่กันทันที
- 🔴 **ห้ามส่งภาพแคปหน้าจอแทน** ตอนที่พี่กันสั่งให้เปิดดูในโครม
- 🔴🔴🔴 **งานที่สั่งไปก่อนหน้า ต้องทำให้เสร็จ แม้จะมีงานใหม่มาแทรก**
  (พี่กันสั่ง 31 ส.ค. 2569 · "งานที่สั่งไปก่อนหน้า ต้องทำให้เสร้จ เเม้จะมาแทรกก้ตาม")
  งานใหม่ที่แทรกเข้ามาไม่ได้ยกเลิกงานเก่า · ทำงานแทรกเสร็จแล้ว **กลับไปทำงานค้างต่อทันที**
  ห้ามปล่อยงานที่สั่งแล้วค้างไว้เงียบ ๆ ห้ามถามซ้ำว่าจะให้ทำต่อไหม
  ตัวช่วยที่ต้องมีติดตัว: จำรายการงานที่สั่งมาแล้วทั้งหมด แล้วไล่เช็คว่าทำครบหรือยังก่อนรายงาน
- 🔴🔴 **หาโครมไม่เจอ = ต้องยิงถามพี่กันว่าใช้โครมอันไหน ห้ามเปิดใหม่เอง**
  (พี่กันสั่งเพิ่ม 31 ส.ค. 2569)
  เปิดแชทใหม่ · เปลี่ยนเครื่องที่นั่งทำงาน · ย้ายไปคอมอีกตัว
  ทั้งหมดนี้ทำให้แคลร์มองไม่เห็นโครมที่พี่กันเปิดอยู่ **ซึ่งไม่ได้แปลว่าไม่มี**
  มันคือโครมของ**เครื่องใหม่**ที่ยังไม่ได้เชื่อมกัน
  → ถามพี่กันตรง ๆ ว่าตอนนี้ใช้โครมอันไหน อย่าเดา อย่าเปิดหน้าต่างใหม่มาแทน
- ⚠️ **แคลร์กรอกรหัสผ่านเองไม่ได้** ถ้าติดหน้าล็อกอิน ให้บอกพี่กันกรอก แล้วค่อยกดต่อ
