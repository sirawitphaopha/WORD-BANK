# หน้าจอมือถือ — กฎกลาง ใช้ได้ทุกโปรเจกต์

> พี่กันสั่ง 1 ก.ย. 2569: *"ห้ามเปลี่ยนเดสก์ท็อปสักนิดเดียว แม้แต่ขยับ 1px ก็ห้าม
> เราเลยอยากทำ มันสร้างไฟล์แยกได้ไหม แบบแก้เฉพาะไฟล์นี้ เป็นของมือถือ"*

---

## ⚡ เจออาการไหน อ่านข้อไหน

ผู้ใช้อธิบายอาการด้วยสิ่งที่เห็น ไม่ใช่ด้วยสาเหตุ — ตารางนี้แปลจากสิ่งที่เห็นเป็นสาเหตุ

| ผู้ใช้บอกว่า | ให้ดูก่อนว่า | สาเหตุที่น่าจะเป็น |
|---|---|---|
| "หน้ามันเลื่อนไปมา" | **อะไรขยับ อะไรไม่ขยับ** ในภาพเดียวกัน | ดู 🏆 ด้านล่าง |
| ของที่ตรึงไว้ยังนิ่ง แต่เนื้อหาไถล | — | **พื้นที่เลื่อนเลื่อนแนวนอนได้** → ดีดกลับด้วย JS |
| ทุกอย่างขยับพร้อมกัน รวมแถบที่อยู่เบราว์เซอร์ | ขนาดตัวอักษรเปลี่ยนไหม | กรอบหน้าเว็บถูกลาก (ซูม หรือของล้น) |
| ตัวอักษร**ใหญ่ขึ้น** ในภาพที่มีอาการ | — | iPhone ซูมเอง → ช่องกรอกเล็กกว่า 16px |
| ตัวอักษร**เล็กลง** เนื้อหาไม่เต็มจอ | — | เบราว์เซอร์ย่อหน้าให้พอดี เพราะมีของกว้างเกิน |
| "แก้แล้วยังไม่หาย" ทั้งที่ตัวตรวจผ่าน | ผู้ใช้ได้โค้ดใหม่จริงหรือยัง | ใส่ป้ายเลขในชื่อเว็บให้ผู้ใช้ยืนยัน |

🚨 **อย่าเดาสาเหตุจากคำอธิบาย** — คำว่า "เลื่อนไปมา" ใช้ได้กับสาเหตุอย่างน้อย 4 แบบ
ที่แก้คนละวิธีกันหมด ขอภาพหรือคลิปแล้วดูว่าอะไรขยับ อะไรไม่ขยับ เสมอ

### ป้ายเลขในชื่อเว็บ — ท่าที่ประหยัดเวลาที่สุด

ก่อนไล่แก้รอบใหม่ ใส่เลขต่อท้ายชื่อเว็บ (`มูลค่ายาคืน 1` → `2` → `3`) ทุกครั้งที่ส่งของใหม่
ผู้ใช้เห็นเลขไหน = ได้โค้ดชุดนั้น ตัดข้อสงสัย "โค้ดถึงหรือยัง" ออกจากสมการทันที

🚨 **ใส่ฝั่งเดียวกับที่กำลังแก้เท่านั้น** (มือถือแก้ ก็ใส่ฝั่งมือถือ) และ**ลบทิ้งทันที**ที่ยืนยันแล้ว

## 🛑 ข้อแรกสุด — แยกไฟล์มือถือออกมาก่อนเสมอ

**ห้ามแก้หน้าจอมือถือด้วยการไปแก้ CSS กลางที่เดสก์ท็อปใช้ร่วมกัน**
ต่อให้แน่ใจแค่ไหนว่าไม่กระทบ — กฎที่ลืมครอบเงื่อนไขจะรั่วไปโดนเดสก์ท็อปแบบเงียบสนิท

### โครงที่ใช้

```
app/globals.css     ของเดิม ห้ามแตะเวลาทำงานมือถือ
app/mobile.css      🆕 ของมือถือทั้งหมด — ทุกบรรทัดขึ้นต้นด้วย .mrv-mobile
```

**ตั้งชื่อคลาสตามโปรเจกต์** (`mrv-mobile` · `drp-mobile` · `hcv-mobile`) ไม่ต้องใช้ชื่อกลาง
จะได้รู้ทันทีว่ากฎนี้ของเว็บไหนเวลาก๊อปข้ามโปรเจกต์

### 🚨 กฎ 3 ข้อของไฟล์นี้ ห้ามฝ่าฝืน

**① ทุกกฎต้องขึ้นต้นด้วยคลาสมือถือ ไม่มีข้อยกเว้น**

```css
/* ✅ */  .mrv-mobile [role="button"]:active { scale: 0.97; }
/* ❌ */  [role="button"]:active { scale: 0.97; }        /* รั่วไปโดนเดสก์ท็อปทันที */
```

**② ห้ามใช้ `@media (max-width: ...)` ตัดสินว่าเป็นมือถือ**

เว็บส่วนใหญ่มีปุ่ม "สลับดูแบบมือถือ" บนคอม — กดแล้วจอยังกว้าง 1366px อยู่
แต่หน้าจอเป็นแบบมือถือแล้ว · media query จะไม่ทำงานเลยในกรณีนั้น

**ต้องผูกกับธงตัวเดียวกับที่ JSX ใช้เลือกว่าจะวาดหน้าจอแบบไหน**

```js
// MedReturnApp.jsx (หรือคอมโพเนนต์แม่ของโปรเจกต์นั้น)
syncMobileClass = () => {
  if (typeof document === 'undefined') return;
  const st = this.state;
  const wide = (st.vw || 0) >= 1180 && !st.forceNarrow;   // ← ต้องตรงกับ vals/derive.js เป๊ะ
  document.body.classList.toggle('mrv-mobile', !wide);
};
```

เรียก 2 จุด — ตอนวัดจอ (`resize`) และตอน `componentDidUpdate` เมื่อ `vw` หรือ `forceNarrow` เปลี่ยน

🚨 **เงื่อนไขต้องตรงกับที่ JSX ใช้เป๊ะ ๆ** แก้ที่หนึ่งต้องแก้อีกที่เสมอ
ไม่งั้น CSS กับ JSX จะไม่ตรงกันแบบไม่มีอะไรเตือน

**③ ห้ามเขียนกฎที่กระทบขนาดหรือตำแหน่งของอะไรก็ตามบนเดสก์ท็อป**
ถ้าไม่แน่ใจว่ากฎไหนรั่ว ให้รันเครื่องมือตรวจ (ดูท้ายไฟล์)

## 📲 เปิดเป็นแอปบนหน้าจอโฮม — ทุกเว็บมือถือต้องทำ

**พี่กันสั่ง 1 ก.ย. 2569: "ข้อ 5 ตั้งเป็นสกิลหลักต้องทำ"**

เว็บที่เจ้าหน้าที่ใช้ทุกวันต้องเปิดจากหน้าจอโฮมได้เหมือนแอปจริง
ไม่ใช่ต้องเปิดเบราว์เซอร์แล้วหาที่อยู่เว็บทุกครั้ง

| ได้อะไร | ทำไมสำคัญ |
|---|---|
| ไอคอนวางบนหน้าจอโฮม | กดเข้าใช้งานได้ในกดเดียว ไม่ต้องพิมพ์ที่อยู่เว็บ |
| เปิดเต็มจอ ไม่มีแถบที่อยู่เว็บ | ได้พื้นที่จอคืนมาราว 90 จุด ซึ่งเยอะมากบนมือถือ |
| สลับแอปแล้วเห็นเป็นแอปแยกตัว | ไม่ปนกับแท็บเบราว์เซอร์อื่นสิบกว่าแท็บ |

### สิ่งที่ต้องมี

**① ไฟล์ประกาศตัวตนของแอป** — Next.js 15 ขึ้นไปใช้ `app/manifest.js`

```js
export default function manifest() {
  return {
    name: 'ชื่อเต็มของเว็บ',            // โชว์ตอนติดตั้ง
    short_name: 'ชื่อสั้น',              // โชว์ใต้ไอคอน ห้ามเกิน 12 ตัวอักษร
    description: '...',
    start_url: '/',
    display: 'standalone',              // 🚨 ตัวนี้แหละที่ทำให้เต็มจอ
    background_color: '#f6f7f4',        // สีตอนกำลังเปิด
    theme_color: '#2f7d5d',             // สีแถบสถานะบนสุด
    orientation: 'portrait',
    icons: [
      { src: '/icon-192.png', sizes: '192x192', type: 'image/png' },
      { src: '/icon-512.png', sizes: '512x512', type: 'image/png' },
      { src: '/icon-512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' }
    ]
  };
}
```

**② ไอคอนเป็นไฟล์ PNG จริง** ขนาด 192 · 512 · 180 (ตัวหลังสำหรับ iPhone)

🚨 **iOS ไม่รับ SVG กับ data URI** ต้องเป็นไฟล์ PNG ใน `public/` เท่านั้น
   เว็บส่วนใหญ่มีไอคอนเป็น SVG อยู่แล้ว แปลงเป็น PNG ได้ด้วย puppeteer
   (เปิดหน้า HTML ที่ฝัง SVG แล้วถ่ายภาพตามขนาดที่ต้องการ)

**③ บอก iOS เพิ่ม** — iPhone ไม่อ่านไฟล์ประกาศตัวตนครบทุกช่อง ต้องบอกซ้ำใน `metadata`

```js
export const metadata = {
  appleWebApp: {
    capable: true,                      // เปิดเต็มจอบน iPhone
    statusBarStyle: 'default',
    title: 'ชื่อสั้น'
  },
  icons: { icon: FAVICON, apple: '/icon-180.png' }
};
```

### 🚨 กับดักที่ต้องรู้

- 🔴 **ต้องเป็น https เท่านั้น** — เปิดผ่าน `http://192.168.x.x` จะไม่มีเมนู "เพิ่มลงหน้าจอโฮม"
  ทดสอบบนเว็บจริงหลัง deploy เท่านั้น เครื่องทดสอบในเครื่องดูไม่ได้
- 🔴 **`display: 'standalone'` ทำให้ไม่มีปุ่มย้อนกลับของเบราว์เซอร์**
  เว็บต้องมีทางกลับของตัวเองทุกหน้า ไม่งั้นผู้ใช้ติดอยู่ในหน้านั้นถาวร
- 🔴 **ไอคอน maskable ต้องเผื่อขอบ** Android ตัดไอคอนเป็นวงกลม/สี่เหลี่ยมมนตามธีมเครื่อง
  ของสำคัญต้องอยู่ในวงกลมกลางภาพ 80% ไม่งั้นโดนตัดขอบ
- 🔴 **`short_name` เกิน 12 ตัวอักษรจะโดนตัดด้วยจุดไข่ปลา** ใต้ไอคอนบนหน้าจอโฮม
- ⚠️ **ไม่ได้แปลว่าใช้ตอนไม่มีเน็ตได้** อันนั้นต้องทำ service worker เพิ่มอีกชุด
  เว็บที่ต้องต่อฐานข้อมูลตลอดเวลาไม่ได้ประโยชน์จากตรงนั้นมากนัก

### วิธีตรวจ

1. เปิดเว็บจริง (https) บนมือถือ → กดปุ่มแชร์ → ต้องเห็น "เพิ่มลงหน้าจอโฮม"
2. เพิ่มแล้วดูไอคอนบนหน้าจอโฮม — ต้องเป็นไอคอนของเว็บ ไม่ใช่ภาพหน้าจอย่อ
3. กดไอคอน → ต้องเปิดเต็มจอ ไม่มีแถบที่อยู่เว็บ
4. ตรวจไฟล์ประกาศตัวตนด้วย `curl https://<โดเมน>/manifest.webmanifest`

## สิ่งที่ทำให้เว็บ "รู้สึกเป็นแอป" — เรียงตามคุ้มที่สุด

### 🟢 ทำก่อน — CSS ไฟล์เดียว ได้ผลเยอะ

| ทำอะไร | ได้อะไร |
|---|---|
| **ปุ่มยุบตอนกด** (`scale: 0.97` ที่ `:active`) | แตะปุ่มปุ๊บรู้ทันทีว่าโดน |
| **`touch-action: manipulation` บนปุ่ม** | ปิดซูมตอนแตะสองครั้ง ปุ่มตอบไวขึ้น |
| **`user-select: none` บนปุ่ม** | แตะปุ่มแล้วตัวหนังสือไม่ถูกลากไฮไลต์ |
| **`overscroll-behavior: contain`** บนกล่องที่เลื่อนได้ | เลื่อนสุดในกล่องแล้วหน้าข้างหลังไม่ไหลตาม |
| **`dvh` แทน `100vh`** | ของไม่ล้นจอตอนแถบเบราว์เซอร์ยืดหด |
| **`env(safe-area-inset-*)`** + `viewportFit: 'cover'` | เนื้อหาไม่โดนติ่งจอกับแถบท่าทางล่างบัง |
| **`:focus-visible` แทน `:focus`** | ปุ่มไม่ค้างขอบเรืองหลังแตะ แต่คีย์บอร์ดยังใช้ได้ |

### 🚨 กับดักที่เจอจริง

**ปิดไฮไลต์ตอนแตะแล้วต้องใส่อะไรแทนเสมอ**

```css
* { -webkit-tap-highlight-color: transparent; }   /* ปิดแล้ว... */
```

ถ้าสีที่ทำไว้ทั้งเว็บเป็น `:hover` ล้วน — **จอสัมผัสไม่มี hover**
ผลคือแตะปุ่มแล้วเงียบสนิท ไม่รู้ว่านิ้วโดนหรือยัง **แย่กว่าไม่ปิดไฮไลต์เลย**

**ใช้ `scale` ไม่ใช่ `transform`**
ปุ่มหลายตัวมี `transform` อยู่แล้ว (เช่นปุ่ม ✕ ที่ใช้ `translateY` จัดกึ่งกลาง)
เขียนทับด้วย `transform` แล้วปุ่มจะกระโดดออกจากตำแหน่งตอนกด

**ตัวเลือกต้องตรงกับปุ่มจริงในโปรเจกต์นั้น**
เว็บที่ปุ่มเป็น `<div role="button">` (ไม่ใช่ `<button>` จริง) ต้องเขียน `[role="button"]`
ก๊อป CSS จากเว็บที่ใช้ `<button>` มาตรง ๆ จะไม่มีผลกับปุ่มสักตัวเดียว

**`user-select: none` ห้ามใส่ทั้งหน้า**
ใส่เฉพาะปุ่มกับป้าย — ไม่งั้นคัดลอกชื่อยา เลข HN เลขเอกสาร ไม่ได้ ซึ่งเป็นการใช้งานจริง

## 🔴 ห้ามทำเด็ดขาด

| อย่าทำ | เพราะ |
|---|---|
| **`navigator.vibrate` (สั่นตอบสนอง)** | **iPhone ไม่รองรับเลยทุกเวอร์ชัน** ([caniuse](https://caniuse.com/vibration)) · ท่าเลี่ยงผ่าน checkbox switch แอปเปิลปิดไปแล้วตั้งแต่ iOS 26.5 · เป็นการอาศัยผลข้างเคียงของบั๊ก |
| **`user-scalable=no` / `maximum-scale=1`** | ผิด WCAG 1.4.4 — **คนสายตายาวซูมอ่านไม่ได้** · ใช้ `touch-action: manipulation` แทนได้ผลเดียวกันโดยไม่ปิดการซูม |
| **ปิดเมนูกดค้างทั้งเว็บ** | คัดลอกข้อมูลไม่ได้ · ทำเฉพาะจุดที่เป็นปุ่ม |
| **`-webkit-overflow-scrolling: touch`** | เลิกใช้แล้ว iOS 13+ ทำให้เองอยู่แล้ว |
| **ซ่อนคอลัมน์ตารางตามความกว้างจอ** | ข้อมูลหายโดยผู้ใช้ไม่รู้ · ให้เลื่อนซ้ายขวาแทน (พี่กันสั่งไว้ที่ HCV) |

## 🚨 พื้นที่กดทับกัน — อันตรายที่สุดบนจอสัมผัส

คลาสที่ขยายพื้นที่กด (เช่น `.tap::before { inset: -11px }`) **ห้ามใส่กับปุ่มคู่ที่วางติดกัน**

ปุ่มที่ห่างกันน้อยกว่า 2 เท่าของระยะที่ขยาย จะมีพื้นที่กดซ้อนกัน
→ เล็งกดปุ่มหนึ่ง แต่โดนอีกปุ่ม **โดยไม่มีอะไรเตือน**

**ทางแก้ที่ถูก** — ขยายตัวปุ่มเองให้ถึง 44px แล้วถอดคลาสขยายพื้นที่กดออก

```jsx
/* ❌ */ <div className="tap" style={s('padding:5px 10px')}>ใช้ต่อ</div>
/* ✅ */ <div style={s('min-height:44px;min-width:56px;display:flex;align-items:center;justify-content:center;padding:5px 12px')}>ใช้ต่อ</div>
```

🚨 **ห้ามแค่ถอดคลาสเฉย ๆ** ปุ่มจะเหลือเล็กกว่าเกณฑ์นิ้ว กดยากกว่าเดิม

**เคสที่ต้องรีบแก้ที่สุด** คือปุ่มคู่ที่ผลลัพธ์ตรงข้ามกัน — ใช้ต่อ ↔ ทำลาย · อนุมัติ ↔ ปฏิเสธ · แก้ ↔ ลบ
กดผิดแล้วข้อมูลเปลี่ยนความหมายทันที

## เครื่องมือพิสูจน์ว่าเดสก์ท็อปไม่ขยับ

## ก่อนลงมือทุกครั้ง

1. **หน้าจอมือถือของเว็บนี้แยก markup หรือ responsive ตัวเดียว** — ดูว่ามี `renderXxxNarrow`/`Wide` ไหม

5. **รันเครื่องมือตรวจก่อนและหลัง** — จะได้รู้ว่าอะไรเปลี่ยนเพราะเราจริง ๆ

## 🔴 หน้าเว็บเลื่อนซ้ายขวาได้ = บั๊กเสมอ

พี่กันถ่ายวิดีโอมาให้ดู 1 ก.ย. 2569: *"เราไม่อยากให้มันเลื่อนไปมาแบบนี้"*
หน้าไถลไปทางขวา 74px ตัวหนังสือฝั่งขวาหายนอกจอ — ป้ายเตือน ปุ่มลบ ชิปตัวสุดท้าย

### กับดักที่ทำให้เกิด — flex คอลัมน์ที่จัดกึ่งกลาง

```jsx
/* พ่อ */ <div style="display:flex;flex-direction:column;align-items:center">
/* ลูก */   <div style="min-width:0">
/*      */     <span style="white-space:nowrap">ข้อความยาว 539px</span>
```

`align-items: center` ทำให้ลูก **ไม่ถูกยืดเต็มความกว้าง** แต่กว้างเท่าเนื้อหาแทน
`min-width: 0` ที่ตัวลูกจึงไม่ช่วยอะไรเลย เพราะไม่มีอะไรมาบีบตั้งแต่แรก

**ทางแก้: `max-width: 100%` ที่ลูก** — บนมือถือให้ขึ้นบรรทัดใหม่ ไม่ตัดด้วยจุดไข่ปลา
(ชื่อหน่วยงานที่เหลือครึ่งเดียวตลอดแย่กว่าสองบรรทัด)

### ประกาศเจตนาที่พื้นที่เลื่อน

```css
.mrv-mobile [role="main"] { overflow-x: hidden; }
```

🚨 **ไม่ใช่ที่ซ่อนขยะ** — ของที่ล้นจริงต้องแก้ที่ตัวมันเสมอ
กฎนี้กันเศษ 1-2px ที่มาจากพื้นที่กดขยายของปุ่มชิดขอบจอ (`::before`) ซึ่งมองไม่เห็นอยู่แล้ว

🚨 **ใส่ที่พื้นที่เลื่อนจริง ไม่ใช่ที่ `body`** — เว็บที่ตรึงความสูงเท่าจอ ตัวที่เลื่อนคือ div ตัวใน

### เครื่องมือ — `scripts/overflow-check.mjs`

วัดจากขนาดจริงของทุกกล่อง ไม่ได้ดูแค่ว่าแถบเลื่อนโผล่ไหม

```
ความกว้างเอกสาร 390 · จอ 390          ← เท่ากัน = ผ่าน
ของที่ยื่นออกนอกจอ
  div "฿ มูลค่ายาคืน v0.15.1.0 · "  ซ้าย -74 ขวา 464 (กว้าง 539)   ← ต้นเหตุ
```

🚨 **ต้องรายงานเฉพาะตัวที่พ่อไม่ได้ล้นด้วย** ไม่งั้นได้รายชื่อลูกหลานที่ล้นตามพ่อเป็นร้อยบรรทัด
🚨 **ต้องตรวจทั้ง `document.scrollWidth` และกล่องที่ `scrollWidth > clientWidth`**
เว็บที่ตรึงความสูง `document` จะไม่โตเลย แต่กล่องข้างในเลื่อนได้ — ดูอย่างเดียวจะไม่เจอ

## ท่ามาตรฐานที่ทำให้รู้สึกเป็นแอป — 2 อย่างที่คุ้มที่สุด

### ① ดึงลงเพื่อโหลดใหม่

```js
PULL_MAX = 92;    // ลากได้ไกลสุด
PULL_FIRE = 62;   // ถึงเท่านี้แล้วปล่อย = สั่งโหลด
```

- 🚨 **ต้องอยู่บนสุดของพื้นที่เลื่อนเท่านั้น** (`scrollTop === 0`) ไม่งั้นเลื่อนดูตารางกลางหน้าแล้วโดนดึงมั่ว
- 🚨 **หารระยะที่นิ้วลากครึ่งหนึ่ง** ให้รู้สึกฝืดเหมือนยางยืด · ลากเท่าไหร่ขยับเท่านั้นจะลื่นเกินจนเผลอสั่งบ่อย
- 🚨 **`touchmove` ต้องผูกแบบ `passive: false`** เพื่อ `preventDefault` ได้ ไม่งั้นการเด้งของเบราว์เซอร์สู้กับของเรา ภาพกระตุก
- 🚨 **`overscroll-behavior-y: contain`** ปิดการรีเฟรชทั้งหน้าของ Chrome แอนดรอยด์ — ไม่งั้นดึงทีเดียวได้สองอย่าง และร่างที่กรอกค้างเสี่ยงหาย
- 🚨 **ตั้งเวลาขั้นต่ำ ~420ms** ไม่งั้นเน็ตเร็ว ๆ ตัวหมุนแวบเดียวจนดูเหมือนไม่ได้ทำอะไร
- 🚨 **ระหว่างลากห้ามมี transition** เขียน `transition:none` ทับใน inline style · ปล่อยนิ้วแล้วค่อยให้ CSS ไล่กลับ
- **ข้อความต้องเปลี่ยนตามระยะ** — "ดึงลงเพื่อโหลดใหม่" → "ปล่อยเพื่อโหลดใหม่" → "กำลังโหลดข้อมูลใหม่"
  ไม่งั้นไม่มีทางรู้ว่าลากพอหรือยัง

### ② เปลี่ยนหน้าไม่วาบ (View Transitions)

```js
if (typeof document.startViewTransition === 'function' && เป็นมือถือ) {
  document.startViewTransition(() => setState({ screen: name }));
} else { setState({ screen: name }); }
```

- 🚨 **ห้ามเขียนแอนิเมชันเอง** — ต้องประวิงการถอด DOM ไว้ ซึ่งพังทันทีที่ state เปลี่ยนระหว่างทาง
- 🚨 **กดแท็บเดิมซ้ำต้องไม่ไล่จาง** เช็ค `screen === name` แล้ว return
- 🚨 **ห้ามใช้กับหน้าต่างซ้อน (ป๊อป)** — ภาพนิ่งที่เบราว์เซอร์ถ่ายไว้จะกินคลิกไปด้วย
- CSS ของมันเป็น pseudo ระดับเอกสาร ซ้อนใต้คลาสไม่ได้ → ล้อมด้วย `:root:has(body.mrv-mobile)`

ติดตั้งครั้งเดียวจบ (พี่กันสั่งเอง 1 ก.ย. 2569 "ไปหาวิธีอ่านวิดีโอมาเดี๋ยวนี้ ติดตั้งเดี๋ยวนี้")

⚠️ ตัวติดตั้งไม่เข้า PATH ของเชลล์ที่เปิดอยู่ ต้องเรียกด้วยที่อยู่เต็ม
(`%LOCALAPPDATA%\Microsoft\WinGet\Packages\Gyan.FFmpeg_*\ffmpeg-*-full_build\bin\ffmpeg.exe`)

**ท่าที่ใช้บ่อยที่สุด — เรียงทั้งคลิปเป็นตารางภาพเดียว** เห็นการเคลื่อนไหวทั้งคลิปในภาพเดียว

```bash
ffmpeg -i clip.mp4 -vf "fps=2.5,scale=250:-1,tile=5x3" -frames:v 1 tile.png
```

| อยากได้อะไร | ใส่อะไร |
|---|---|
| ทั้งคลิปในภาพเดียว | `fps=2.5,scale=250:-1,tile=5x3` |
| ดูจุดเล็ก ๆ ชัด ๆ | `-ss <วินาที> -frames:v 1 -vf "crop=กว้าง:สูง:x:y,scale=400:-1"` |
| เทียบสองจังหวะ | ตัดสองภาพแล้ว `-filter_complex "[0:v][1:v]vstack=inputs=2"` |

🚨 **ดูให้ครบทั้งคลิป ไม่ใช่เฟรมเดียว** — สิ่งที่บอกสาเหตุคือ "อะไรขยับ อะไรไม่ขยับ"
ซึ่งเห็นได้จากการเทียบหลายเฟรมเท่านั้น

### ทางสำรอง — ถ้าลง ffmpeg ไม่ได้

Chrome เล่น mp4 ได้อยู่แล้ว ใช้ puppeteer เปิดหน้า HTML ที่มี `<video>` แล้ว seek ทีละจังหวะ

- 🚨 ต้องเปิด `--allow-file-access-from-files` ไม่งั้น canvas ถูกปนเปื้อนแล้วอ่านภาพออกมาไม่ได้
- 🚨 ก๊อปวิดีโอมาไว้ข้างไฟล์ HTML ชื่อสั้น ๆ — ชื่อไฟล์ที่ผู้ใช้ส่งมามักยาวและมีอักขระแปลก

## 🔴🔴 เทสสถานะเดียวไม่พอ — บั๊กชอบซ่อนในเส้นทางที่ไม่ได้เทส

**เจอซ้ำรอบสอง 1 ก.ย. 2569** — พี่กันส่งคลิปมาว่า *"มันยังเลื่อนไปมาได้อยู่เลยยยยยยย"*
ทั้งที่รอบแรกแก้ไปแล้วและเครื่องมือตรวจรายงานว่าผ่าน

**ต้นเหตุรอบสองคนละตัวกับรอบแรก** — แถบแจ้งเตือนหัวหน้าจอวาดคนละแบบตามจำนวนรายการ

| สถานะ | หน้าตา | กว้างรวม |
|---|---|---|
| หลายรายการ | ข้อความ + ปุ่มเดียว | ~340px ✅ |
| **รายการเดียว** | ข้อความเต็ม + **ปุ่ม 3 ปุ่ม** | **~507px** 🔴 ล้น 117px |

เครื่องมือตรวจรอบแรกเทสตอนมี 2 รายการ จึงผ่านหมด ส่วนของจริงพี่กันมีรายการเดียว

🚨 **ทุกสถานะที่วาดต่างกัน = คนละเส้นทาง ต้องเทสแยกทุกอัน**
`items.length === 1` · `=== 0` · `> 5` · มีข้อมูล/ไม่มี · เชื่อมต่อได้/ไม่ได้
เทสอันเดียวแล้วเหมาว่าอีกอันก็ผ่าน คือการหลอกตัวเอง

**เครื่องมือที่ถูก** — ยัดข้อมูลปลอมเข้า state แล้ววัดทุกสถานะในรอบเดียว

```js
for (const [n, label] of [[1,'รายการเดียว'], [2,'สองรายการ'], [7,'เจ็ดรายการ']]) {
  await setState(page, n);
  const m = await measure(page, W);
  ok(m.over.length === 0, label, 'ล้น: ' + m.over.map(x => x.t).join(', '));
}
```
🚨 คูณด้วยขนาดจอด้วย — 390 (iPhone เล็ก) และ 440 (ตัวใหญ่)

### `min-width` บนกล่องที่ต้องยอมหด

```jsx
/* ❌ */ 'flex:1;min-width:180px'   // ที่ไม่พอก็ไม่หด ดันปุ่มล้นออกนอกจอแทน
/* ✅ */ minWidth: wide ? '180px' : 0
```

`min-width` ที่ตั้งไว้เพื่อความสวยบนจอกว้าง กลายเป็นตัวดันของล้นบนจอแคบเสมอ

### ตาข่ายชั้นสุดท้าย — iOS ลากทั้งหน้าจอ ไม่ใช่แค่กล่องข้างใน

สังเกตจากคลิป: **แถบที่อยู่ของ Safari เลื่อนตามไปด้วย**
นั่นแปลว่าไม่ใช่กล่องข้างในเลื่อน แต่เป็น iOS ที่ยอมให้ลากทั้งหน้าเมื่อมีอะไรกว้างเกิน

```css
.mrv-mobile, html:has(body.mrv-mobile) { overflow-x: hidden; max-width: 100vw; }
```

🚨 กฎที่คุมเฉพาะพื้นที่เลื่อนของเว็บไม่พอสำหรับกรณีนี้ — ต้องคุมถึง `html` ด้วย
🚨 ยังต้องแก้ต้นเหตุที่ตัวมันเสมอ กฎนี้เป็นตาข่าย ไม่ใช่ที่ซ่อนของล้น

Safari บน iPhone **ซูมหน้าเข้าเองทันที**เมื่อแตะช่องกรอกที่ `font-size` เล็กกว่า **16px**
แล้ว **ไม่ซูมกลับให้เอง** — หน้าค้างในสภาพซูม ซึ่งลากไปมาได้ทั้งหน้า รวมแถบที่อยู่

ผู้ใช้จะอธิบายว่า "เว็บมันเลื่อนไปมา" ไม่ใช่ "เว็บมันซูม" เพราะสิ่งที่เขาเห็นคือการเลื่อน

### วิธีแยกจาก "ของล้นจอ" — ดูขนาดตัวอักษร ไม่ใช่ตำแหน่ง

ขอภาพสองใบ ใบหนึ่งตอนปกติ ใบหนึ่งตอนมีอาการ แล้วเทียบ

| สังเกต | แปลว่า |
|---|---|
| ตัวอักษร**ใหญ่ขึ้น** ในใบที่มีอาการ | 🔴 ซูม |
| ตัวอักษรขนาดเท่ากัน แค่เลื่อนไปข้าง | ของล้นจอ |
| แถบล่างที่ตรึงไว้**ขนาดไม่เปลี่ยน** ทั้งที่เนื้อหาใหญ่ขึ้น | ยิ่งยืนยันว่าซูม |

### ทางแก้

```css
.mrv-mobile input:not(.mrv-qty-big),
.mrv-mobile select,
.mrv-mobile textarea { font-size: 16px !important; }
```

- 🚨 **16px คือเส้นตายของ iOS** ห้ามลดเป็น 15.5px เพื่อความสวย มันจะกลับมาซูมทันที
- 🚨 **ห้ามแก้ด้วย `user-scalable=no` / `maximum-scale=1`** — นั่นคือห้ามคนซูม ผิด WCAG 1.4.4
  ทางที่ถูกคือทำให้ตัวอักษรถึง 16px จริง แล้ว iOS ไม่ซูมเอง แต่คนยังซูมได้ตามใจ
- 🚨 **ยกเว้นช่องที่ตั้งใจให้ใหญ่** (ช่องจำนวนตัวเลขโต ๆ) ด้วย `:not(.ชื่อคลาส)` ไม่งั้นกฎย่อมันลง
- ⚠️ ช่องบางช่องโตขึ้นแล้วอาจดันของล้น — รันตัวตรวจ overflow ซ้ำหลังแก้เสมอ

### เครื่องมือ — `scripts/ios-zoom-check.mjs`

**Chrome บนคอมไม่ auto-zoom** ตัวตรวจหน้าตาปกติจึงผ่านหมดทั้งที่ของจริงพัง
ต้อง**วัดขนาดตัวอักษรของทุกช่องตรง ๆ** แทนการดูอาการ

```js
for (const e of document.querySelectorAll('input, select, textarea')) {
  if (e.type === 'hidden' || e.disabled || e.readOnly) continue;   // แตะไม่ได้ ไม่นับ
  if (parseFloat(getComputedStyle(e).fontSize) < 16) แจ้งว่าตก
}
```

🚨 **ต้องไล่ทุกหน้าและทุกหน้าต่างซ้อน** ช่องที่ทำให้ซูมมักอยู่ในหน้าที่เข้านาน ๆ ครั้ง
🚨 **ต้องมีข้อที่ตรวจว่าฝั่งคอมยังใช้ขนาดเดิม** ไม่งั้นกฎรั่วไปโดนเดสก์ท็อปแล้วไม่มีใครรู้

### 🔑 บทเรียนที่แพงที่สุด

**อาการเดียวกันเกิดจากคนละต้นเหตุได้** — แก้ตัวหนึ่งแล้วอาการไม่หาย
อย่าเถียงว่า "แก้แล้ว" หรือ "เครื่องมือบอกว่าผ่าน" ให้หาสาเหตุที่สองต่อ
เครื่องมือที่ผ่านหมดแปลว่า "ไม่ใช่สาเหตุที่เครื่องมือตัวนั้นวัด" ไม่ได้แปลว่าไม่มีปัญหา

## 🏆 หน้าไถลซ้ายขวาบนมือถือ — วิธีที่แก้ได้จริง (หลังลองผิด 7 รอบ)

**1 ก.ย. 2569** พี่กันบ่นเรื่องเดียวกัน 7 รอบติด ถ่ายคลิปมาให้ดู 5 คลิป
กฎ CSS ทุกข้อที่ลองมา **ได้ผลบนคอมแต่ไม่ได้ผลบนมือถือจริงสักข้อ**

### สิ่งที่ลองแล้ว "ไม่พอ" (แต่ยังควรมีไว้)

| ทำอะไร | ทำไมไม่พอ |
|---|---|
| แก้ของที่ล้นจอทีละตัว | มือถือแต่ละรุ่นวาดฟอนต์กว้างไม่เท่ากัน ไม่มีวันจบ |
| `overflow-x: hidden / clip` | ได้ผลบนคอม บนมือถือจริงยังลากได้ |
| `touch-action: pan-y` | เหมือนกัน |
| `max-width: 100vw` ทุกชั้น | เหมือนกัน |
| `position: fixed` ทั้งแอป | fixed ยึดกับ **กรอบผัง** ไม่ใช่ขอบจอ จึงถูกลากไปด้วย |
| วัดขอบจอแล้วล็อกความกว้าง | ล็อกได้จริง แต่ยังลากได้ |
| ห้ามซูม (`user-scalable=no` + ดัก gesture) | ปิดการซูมได้จริง แต่คนละเรื่องกับการลาก |

### ✅ สิ่งที่แก้ได้จริง — ดีดตำแหน่งเลื่อนกลับ 0

เลิกห้าม แล้วปล่อยให้ดันไป **แต่ดีดกลับเป็น 0 ทันทีทุกครั้ง**

```js
_pinLeft = () => {
  if (!document.body.classList.contains('mrv-mobile')) return;   // 🚨 คอมต้องไม่โดน
  const sc = this.scrollRef.current;
  if (sc && sc.scrollLeft !== 0) sc.scrollLeft = 0;
  const de = document.documentElement;
  if (de && de.scrollLeft !== 0) de.scrollLeft = 0;
  if (document.body.scrollLeft !== 0) document.body.scrollLeft = 0;
  if (window.scrollX !== 0) window.scrollTo(0, window.scrollY);
};

document.addEventListener('scroll', this._pinLeft, { passive: true, capture: true });
window.addEventListener('scroll',   this._pinLeft, { passive: true });
window.addEventListener('touchmove', this._pinLeft, { passive: true });
window.addEventListener('touchend',  this._pinLeft, { passive: true });
```

- 🚨 **ต้องดัก `touchmove` ด้วย** — บางเบราว์เซอร์ไม่ยิง `scroll` ระหว่างนิ้วยังลากอยู่ ดักแค่ scroll จะเห็นภาพไถลก่อนแล้วค่อยดีดกลับ
- 🚨 **ต้อง `capture: true` ที่ document** — จับกล่องข้างในที่เลื่อนเองได้ทุกตัว ไม่ใช่แค่ตัวที่รู้จัก
- 🚨 **`passive: true` ได้และควรใช้** — ไม่ได้ห้ามเหตุการณ์ แค่ตั้งค่ากลับ จึงไม่ถ่วงการเลื่อนขึ้นลงเลย
- 🚨 **ต้องเช็คว่าเป็นมือถือก่อนเสมอ** — ตารางกว้างฝั่งคอมต้องเลื่อนดูข้าง ๆ ได้จริง

### 🔑 บทเรียนที่แพงที่สุดของงานนี้

**คำถามของผู้ใช้คือคำตอบ** — พี่กันถามว่า *"ทำไมกรอบปุ่มกดส่งยาไม่เลื่อน ทำไมเอาระบบนั้นมาไม่ได้"*
นั่นชี้ตรงจุดว่าปัญหาอยู่ที่ "พื้นที่เลื่อน" ไม่ใช่ทั้งหน้า ซึ่งเปลี่ยนวิธีแก้ทั้งหมด

- ทุกอย่างขยับพร้อมกันหมด รวมแถบที่อยู่ของเบราว์เซอร์ → กรอบหน้าเว็บถูก pan (ซูมหรือของล้น)
