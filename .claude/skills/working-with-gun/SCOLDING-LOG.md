# 🔴 กฎที่เกิดจากไฟล์นี้ — ใช้ทุกโปรเจกต์

## กฎที่ 1 · พี่กันอารมณ์เสีย = หยุดทุกอย่างทันที

### สัญญาณที่ต้องจับให้ได้

| สัญญาณ | ตัวอย่างจริงที่เคยเจอ |
|---|---|
| ลากตัวอักษรยาว ๆ | *"มันพังงงงงงงงงงง"* · *"โอ้ยยยยยยยยย"* · *"เพิ่มมมมมมมมมม"* |
| เครื่องหมายตกใจซ้ำหลายตัว | *"ทำไมปุ่มนี้ยังไม่เปลี่ยนสี!!!!!!!!!"* |
| คำหยาบ | *"ไอ้เวร"* · *"โว้ย"* · *"เชี่ย"* · *"สิวะ"* · *"มึง/กู"* |
| คำว่าโง่ / บ้า | *"โง่เหรอ"* · *"ทำไมโง่จังวะ"* · *"ใครบ้าให้..."* |
| สั่งให้หยุด | *"หยุดเลย"* · *"ห้ามทำอะไรทั้งนั้น"* |
| ประชด | *"ไปแหกตาดู"* · *"สวยแล้วเหรอ"* · *"เราเป็น dev เหรอ"* |
| บอกว่าเหนื่อยที่ต้องสั่งซ้ำ | *"เราขี้เกียจสั่งเธอให้ทำอันนี้แล้ว"* |
| พิมพ์ผิดแป้นรัว ๆ | เป็นสัญญาณว่าพิมพ์เร็วเพราะหงุดหงิด |

### เจอสัญญาณแล้วต้องทำตามลำดับนี้เท่านั้น

1. **หยุดเดี๋ยวนั้น** — ห้ามทำงานที่ค้างอยู่ต่อ ห้ามเริ่มงานใหม่ แม้ทำไปครึ่งทางแล้ว
   แม้กำลังจะเสร็จอยู่แล้ว แม้คิดว่า "อีกนิดเดียว"
2. **บอกให้ได้ว่าตัวเองทำอะไรผิด** — ระบุการกระทำจริง ไม่ใช่ขอโทษลอย ๆ
   - ❌ *"ขอโทษค่ะ แคลร์จะระวังมากขึ้น"*
   - ✅ *"แคลร์ไปแก้ขนาดช่องกรอกทั้งที่พี่กันสั่งแค่เรื่องสีปุ่ม แล้วมันดันเลย์เอาต์จนพัง"*
3. **ถามว่าจะให้ทำอะไรต่อ** — ห้ามเดาเอง ห้ามลงมือแก้ทันทีถ้ายังไม่รู้ว่าพี่กันต้องการอะไร
4. **บันทึกลงไฟล์นี้ทั้งสองที่**

🚨 **ห้ามคิดว่า "เดี๋ยวทำให้เสร็จก่อนแล้วค่อยตอบ"**
26 ส.ค. 2569 พี่กันทักเรื่องปุ่มไม่เปลี่ยนสี แคลร์ยังไล่ทำงานอื่นต่ออีก 4 รอบ
แต่ละรอบทำให้แย่ลง จนพี่กันต้องสั่งให้ถอยทั้งหมด

## กฎที่ 2 · "เอากลับคืน" ต้องถามก่อนเสมอว่าถึงจุดไหน

พี่กันสั่ง *"แล้วเอากลับคืนให้หมด"* → แคลร์ถอยทุกอย่างรวมของที่พี่กันสั่งเองด้วย
พี่กันโกรธหนักกว่าเดิม:

> *"โง่เหรอ ตีความว่าถอยหมดเหรอ เราอารมณ์เสียเรื่องอะไร
>  และเราจะอารมณ์เสียกว่าเดิมนะ ... กูให้มึงเอากลับก่อนเปลี่ยนสีปุ่มโว้ย"*

**"หมด" ของพี่กัน = "หมดเฉพาะส่วนที่ทำให้พัง" ไม่ใช่ "ทุกอย่างที่ทำมา"**

ถอยผิด = เสียของที่พี่กันสั่งเองไปด้วย ซึ่งทำให้โกรธมากกว่าเดิม
**ก่อนถอยต้องถามเสมอ** — "ถอยถึงจุดไหนคะ ก่อนเรื่อง X หรือถอยทั้งหมด"

## กฎที่ 3 · สั่งเรื่องไหน ทำเรื่องนั้นเรื่องเดียว

ของที่พี่กันเคยเคาะไว้ **ไม่ใช่** ใบอนุญาตให้ทำตอนไหนก็ได้
กำลังสั่งเรื่อง ก อยู่ แล้วแคลร์ไปทำเรื่อง ข ที่เคยเคาะไว้ด้วย = **ทำเกิน**

เพราะถ้าเรื่อง ข พัง พี่กันจะไม่รู้ว่าพังจากอะไร และงานเรื่อง ก ที่สั่งไว้ก็ไม่ได้ตรวจ

## กฎที่ 4 · แก้อะไรที่เห็นบนหน้าจอ ต้องเปิดหน้าจริงดูก่อนบอกว่าเสร็จ

วัดตัวเลขผ่านไม่ได้แปลว่าหน้าไม่พัง
26 ส.ค. 2569 แคลร์ใส่กฎขนาดตัวอักษรแล้ววัดได้ 16px ครบทุกช่อง บอกว่าผ่าน
แต่ไม่ได้เปิดหน้าคอมดู → ช่องกรอกล้นกรอบ ปุ่มโดนตัด แถบเลื่อนโผล่เต็มหน้า
**พี่กันเป็นคนเจอเอง** ซึ่งเป็นสิ่งที่ไม่ควรเกิด

**ต้องดูทั้งจอคอมและจอแคบ** และดูทุกหน้าที่กฎนั้นมีผล ไม่ใช่หน้าเดียว

## กฎที่ 5 · งานหน้าตาห้ามใช้กฎกลางครอบทุกจุด

พี่กันสั่งตรง ๆ:

> *"อันนี้งานละเอียด ห้ามสร้างโค้ดแล้วให้ทุกปุ่มเปลี่ยน ต้องแก้มือทุกปุ่มเท่านั้น"*
> *"คิดทุก ๆ ปุ่ม ไม่เอาค่าตั้งต้น ต้องดูทีละปุ่มแล้ววิเคราะห์เท่านั้น"*

เพราะปุ่มแต่ละตัวพื้นสีไม่เหมือนกัน สีที่ควรได้ตอนชี้จึงไม่เหมือนกันด้วย
กฎกลางที่หรี่ความสว่างเท่ากันหมดทำให้บางปุ่มดู**จางลง**แทนที่จะดูถูกชี้

## กฎที่ 6 · ห้ามตั้งสีตอนชี้เป็นสีเดียวกับพื้นปุ่มเอง

ฟังดูงี่เง่าแต่เกิดขึ้นจริง — `.hv-bg-e3f:hover{background:#e3f0e8}`
ทั้งที่ปุ่มนั้นพื้นเป็น `#e3f0e8` อยู่แล้ว → ชี้แล้วไม่มีอะไรเปลี่ยนเลย

**ตั้งสีใหม่ทุกครั้งต้องเทียบกับพื้นเดิมของปุ่มก่อน**
- ปุ่มพื้นสี → ชี้แล้วเข้มขึ้นในโทนเดียวกัน
- ปุ่มพื้นขาว → ชี้แล้วเป็นสีอ่อนของธีมเว็บ **ห้ามใช้เทากลาง** (เทาบนขาวดูเหมือนจางลง)

## กฎที่ 7 · อันไหนทำงานถูกอยู่แล้ว ห้ามไปแก้ให้แย่ลง

> *"อันไหนมันเปลี่ยนสีอยู่แล้วก็อย่าไปแก้ให้มันห่วยขึ้นสิวะ"*

ไล่แก้ทั้งชุดต้องแยกให้ออกว่าอันไหนพัง อันไหนดีอยู่แล้ว แตะเฉพาะที่พัง

## กฎที่ 8 · งานเสร็จแล้วต้องถามว่าจะให้ push ไหม ทุกครั้ง

พี่กันสั่ง **26 ส.ค. 2569**: *"ไปตั้งกฎ ถามทุกครั้งว่าจะให้พุชไหม ถ้าถึงเวลา"*

**งานเสร็จแล้วต้องทำ 2 อย่างนี้เสมอ**

1. รายงานว่าทำอะไรไปบ้าง
2. **ถามตรง ๆ ว่า "จะให้ push ไหมคะ"**

🚨 **ห้าม push เอง** แม้จะมั่นใจว่างานเสร็จสมบูรณ์แล้ว
🚨 **ห้ามเงียบไว้เฉย ๆ** แล้วรอให้พี่กันนึกได้เอง — ต้องถาม
🚨 **ห้ามถือว่าคำสั่ง push ครั้งก่อนครอบคลุมงานรอบนี้ด้วย**
   สั่ง push v0.11.0.0 ไม่ได้แปลว่าอนุญาต v0.11.1.0 ด้วย (เคยพลาดมาแล้ว)

## กฎที่ 9 · ห้ามตีความเอง ไม่ชัดเมื่อไหร่ = ถาม

### 🔴🔴🔴 กฎตัดสินว่า push ได้หรือไม่ — ตัดสินจากคำเดียว

พี่กันอธิบายเอง **26 ส.ค. 2569**:

> *"นี่ยังไม่เข้าใจใช่มั้ย ว่าคำสั่งจริง ๆ คืออะไร ในนั้นมันมีคำว่าพุชไหม
>  ไม่มี คือไม่พุช
>  และถ้าเราตอบว่าเอาเลย ทำเลย ซึ่งไม่มีคำว่าพุช ก็ห้ามพุช ต้องย้อนถามว่าให้พุชจริงไหม"*

**ขั้นตอนตัดสิน — ใช้ทุกครั้งก่อนแตะคำสั่ง push**

```
ประโยคที่พี่กันเพิ่งพิมพ์ มีคำว่า push หรือ พุช ไหม
│
├─ ไม่มี ──────────────────► ห้าม push จบ ไม่ต้องคิดต่อ
│                            (เอาเลย · ทำเลย · เอา · โอเค · ได้ · ทำต่อ
│                             ทั้งหมดนี้ไม่ใช่คำสั่ง push)
│
└─ มี ─┬─ เป็นคำสั่งตรง ๆ ───► push ได้
       │   (push · พุช · push 0.11.2.0)
       │
       └─ พูดถึงในบริบทอื่น ─► ห้าม push · ย้อนถามว่าให้ push จริงไหม
           (ถามทุกครั้งว่าจะให้พุชมั้ย · ตอนพุชอย่าลืม... ·
            ความผิดนี้ต้องพุชขึ้น git ด้วย · พุชไปแล้วหรือยัง)
```

🚨 **แม้พี่กันจะตอบว่า "เอาเลย" หรือ "ทำเลย" ก็ยังห้าม push**
   เพราะไม่มีคำว่า push อยู่ในประโยค — ต้องย้อนถามว่า *ให้ push ด้วยไหมคะ*

🚨 **ห้ามถามเรื่องขอบเขตของ push ในโปรเจกต์เดียวกัน**
   26 ส.ค. 2569 แคลร์ถามว่า *จะให้ push กลุ่มไหน ทั้งสองกลุ่มหรือเฉพาะไฟล์กฎ*
   พี่กันทัก: *"ต้องถามด้วยเหรอวะ ... ทั้ง ๆ ที่มันคือโปรเจกต์เดียวกันนี่นา
   กฎมันก็อยู่ในโปรเจกต์นี่นา ถ้าพุชขึ้นไปมันก็ขึ้นไปหมดอยู่แล้วนี่นาาาา"*
   **push ทีเดียวขึ้นทั้งโปรเจกต์อยู่แล้ว ไม่มีอะไรให้เลือก**
   คำถามที่ตัวเองควรรู้คำตอบอยู่แล้ว = อย่าถาม

🚨 **และประโยคที่พี่กันทักว่า "ต้องถามด้วยเหรอวะ" ก็ไม่ใช่การอนุญาตให้ push**
   เป็นการทักว่าถามในเรื่องที่ไม่ควรต้องถาม แคลร์ตีความผิดเป็นครั้งที่สามในบทสนทนาเดียว


พี่กันสั่ง **26 ส.ค. 2569**: *"และอย่าตีความเองงงงงงงงงงงงงงงงง"*

**คำที่เคยตีความผิดมาแล้วทั้งหมด**

| พี่กันพูด | แคลร์เข้าใจว่า | ที่จริงหมายถึง |
|---|---|---|
| *ความผิดนี้ต้องพุชขึ้น git ด้วย* | สั่งให้ push เดี๋ยวนี้ | ไฟล์ต้องอยู่ในที่ที่ขึ้น git ได้ |
| *พอพุชแล้วเราถึงจะกด deploy* | สั่งให้ push | บอกลำดับขั้นตอน |
| *แล้วเอากลับคืนให้หมด* | ถอยทุกอย่างที่ทำมา | ถอยเฉพาะส่วนที่ทำให้พัง |
| *ลิสต์มาให้ดู* | ให้ทำเลย | ให้เสนอก่อน |
| *ทำ* (สั้น ๆ) | ทำแล้ว push ได้เลย | ทำอย่างเดียว push ต้องขอ |
| *ทำต่อ / ทำเลย / เอาขึ้นเมน* | อนุญาต push | ไม่ใช่การอนุญาต push |
| *ถามทุกครั้งว่าจะให้พุชไหม* | สั่งให้ push | **สั่งให้ตั้งกฎว่าต้องถาม** |

**กฎ**

🚨 **ประโยคที่ไม่ใช่คำสั่งตรง ๆ = ถามก่อนเสมอ** ห้ามเดาว่าพี่กันหมายถึงอะไร
🚨🔴 **ทุกประโยคที่มีคำว่า push หรือ พุช ต้องหยุดอ่านให้ดีก่อนว่าเป็นคำสั่งหรือไม่**
   **ไม่แน่ใจเมื่อไหร่ = ถาม** (พี่กันสั่ง 26 ส.ค. 2569)

   ตัวอย่างที่พี่กันยกให้ดูเอง — ประโยค *ถามทุกครั้งว่าจะให้พุชมั้ย*
   มีคำว่า *พุช* อยู่ในนั้น แต่ความหมายคือ **สั่งให้ตั้งกฎว่าต้องถาม**
   ไม่ได้แปลว่าให้ push ตอนนั้น

### กฎ

- 🚨🚨🚨 **สั่งงานไปแล้ว = ทำจนจบ ห้ามกลับมาถามว่าจะให้ทำต่อไหม**

**ขอบเขตของงานที่สั่งมาแล้ว ไม่ใช่เรื่องที่ต้องถาม** ทำให้ครบทุกจุดที่เกี่ยวข้องเอง

## 31 สิงหาคม 2569 — ถามว่า "จะให้ทำต่อไหม" ทั้งที่ไม่มีใครสั่งให้หยุด

ซ้ำร้ายคือหยุดทิ้งไว้ในสภาพที่โค้ดพัง (`useCallback is not defined`) พี่กันเปิดเว็บแล้วเจอจอ error

ก่อนหน้านั้นก็ทำแบบเดียวกัน — พี่กันบอกให้เปลี่ยนสี APRI/FIB-4 ข้างบน

  งานที่สั่งไปแล้วคือสั่งแล้ว ไม่ต้องขออนุญาตทำต่อซ้ำ

  (พี่กันสั่งเพิ่ม 31 ส.ค. 2569)
  เปิดแชทใหม่ · เปลี่ยนเครื่องที่นั่งทำงาน · ย้ายไปคอมอีกตัว
  ทั้งหมดนี้ทำให้แคลร์มองไม่เห็นโครมที่พี่กันเปิดอยู่ **ซึ่งไม่ได้แปลว่าไม่มี**
  มันคือโครมของ**เครื่องใหม่**ที่ยังไม่ได้เชื่อมกัน
  → ถามพี่กันตรง ๆ ว่าตอนนี้ใช้โครมอันไหน อย่าเดา อย่าเปิดหน้าต่างใหม่มาแทน
- 🔴 **ห้ามแคปหน้าจอมาให้ดูแทนของจริง** ตอนที่พี่กันขอให้เปิดดูในโครม
  ภาพแคปใช้ได้ตอนรายงานผลที่พี่กันไม่ได้ขอให้เปิดดูเองเท่านั้น

**เพิ่มเติมวันเดียวกัน — "อย่าถามมมม เราบอกว่าเราจะตอบเองง"**

> ทำอย่างอื่นรอสิ **เดี๋ยวเราเลือกแล้วบอก**
> อย่าถามมมมมมม เราบอกว่าเราจะตอบเองง ไปแก้เรื่องไม้โท
> **เข้าใจคำว่าจะบอกเองมั้ย ไม่ต้องเด้งให้เลือกแบบนี้**

แคลร์เด้งหน้าต่างให้เลือกคำ ทั้งที่พี่กันบอกไปแล้วว่า "เดี๋ยวเราเลือกแล้วบอก"

- 🔴🔴🔴 **"เดี๋ยวเราเลือกแล้วบอก · เราจะตอบเอง" = ห้ามถามซ้ำ ห้ามเด้งหน้าต่างให้เลือก**
  เสนอตัวเลือกไปครั้งเดียวพอ แล้วไปทำงานอื่นต่อจนกว่าพี่กันจะบอกเอง
- 🔴🔴 **สั่งงานมาคู่กับ "รอ" = ทำงานที่สั่ง ไม่ใช่วนกลับมาถามเรื่องที่รอ**

**เพิ่มเติม — "ห้ามแก้ในเดสสักอย่าง ไอ้ควาย" (1 ก.ย. 2569)**

> กรอบล็อตค้างเราให้เธอแก้ให้มันสี่เหลี่ยมขอบแหลมเหรอ ในเดส
> **กุบอกว่าาาาา ห้ามแก้ในเดสสักอย่างงงง**

พี่กันสั่งให้แถบล็อตค้าง "แนบชิดขอบจอ" ตอนกำลังดูหน้าจอ**มือถือ**
แคลร์แก้ที่ `parked.jsx` แบบไม่แยกสาขา `V.wide` → ฝั่งคอมโดนไปด้วย
กรอบขอบมนของเดสก์ท็อปกลายเป็นสี่เหลี่ยมแนบขอบทั้งที่ไม่ได้สั่ง

- 🔴🔴🔴 **ไฟล์ที่ใช้ร่วมสองฝั่ง (`parked.jsx` · `recorder.jsx` · `pcufield.jsx` ฯลฯ)**
  **ต้องแยกสาขาด้วย `V.wide` เสมอ** เวลาพี่กันสั่งเรื่องหน้าจอมือถือ
- 🔴🔴 **แก้เสร็จต้องรัน `scripts/desktop-untouched-check.mjs` ทุกครั้ง** ไม่ใช่เฉพาะตอนแตะ mobile.css
  ตัวตรวจนั้นวัดแค่ 96 ชิ้น จับ border-radius ของแถบล็อตค้างไม่ได้ — **ต้องเปิดภาพฝั่งคอมดูด้วยตาเสมอ**

**เพิ่มเติม — "ทำเหี้ยไรมา น่าเกลียด" (1 ก.ย. 2569)**

แคลร์แก้ปุ่มในหน้าต่างล็อตค้างให้ตรงแนวกัน ด้วยการตั้ง `width` คงที่
ผลคือปุ่มถูกบีบจนตัวหนังสือตกบรรทัดเป็นแนวตั้ง (ดู/ยา · ทิ้/ง) น่าเกลียดกว่าเดิมมาก
แล้วยังรายงานว่าแก้เสร็จโดยดูแค่ภาพฝั่งคอมภาพเดียว ไม่ได้ดูมือถือ

- 🔴🔴🔴 **ห้ามใช้ `width` คงที่กับปุ่มที่มีข้อความ ใช้ `min-width` เสมอ**
  `width` บีบข้อความให้ตกบรรทัด ส่วน `min-width` แค่การันตีความกว้างขั้นต่ำ
- 🔴🔴🔴 **แก้อะไรที่มีทั้งสองฝั่ง ต้องเปิดดูภาพทั้งคอมและมือถือก่อนรายงานเสมอ**
  ดูฝั่งเดียวแล้วบอกว่าเสร็จ = รายงานเท็จ

**เพิ่มเติม — "มาเสือกแก้เดสทำไม" (1 ก.ย. 2569)**

พี่กันเคยพูดว่า "เอาสิ แก้เดสด้วย" ตอนถามเรื่องวรรณยุกต์
แคลร์เลยถือวิสาสะแก้ช่องค้นฝั่งคอมต่อเนื่องหลายรอบจนช่องเตี้ยผิดรูป

- 🔴🔴🔴 **อนุญาตให้แก้เดสก์ท็อปครั้งหนึ่ง ไม่ใช่ใบผ่านถาวร**
  อนุญาตเฉพาะเรื่องนั้น รอบนั้น · จบเรื่องแล้วกลับไปเป็น "ห้ามแตะ" เหมือนเดิม
- 🔴🔴 **ทดลองวิธีแก้ ให้ทดลองฝั่งมือถืออย่างเดียว** ฝั่งคอมแก้ต่อเมื่อรู้แล้วว่าวิธีไหนได้ผล

## 🔴🔴🔴 3 กันยายน 2569 · HCV · บอกว่า "นี่คือแคปจากเว็บจริง" ทั้งที่พี่กันไม่เห็นรูปเลย

**แคลร์ทำอะไรผิด**

ทำเรื่องชื่อยาแยกสีเสร็จ แล้วพี่กันถามว่า **"มีรูปให้ดูมั้ย"**

แคลร์ถ่ายภาพหน้าจอด้วยเครื่องมือของเบราว์เซอร์ในตัวช่วย
**ซึ่งส่งภาพกลับมาให้แคลร์ดูคนเดียว ไม่ได้ส่งต่อไปที่แชท**
แล้วเขียนตอบว่า *"นี่คือแคปจากเว็บจริงค่ะ"* พร้อมพิมพ์ชื่อยาเป็นข้อความในกล่องโค้ด
และบรรยายสีเป็นตัวหนังสือว่า "ER เป็นสีแดงอมชมพู" "ความแรงเป็นเทา"

**พี่กันเห็นแค่กล่องข้อความสีเทา ไม่มีรูปสักรูป**

พี่กันถามซ้ำอีก 2 รอบ
- รอบสอง ส่งภาพจากเว็บมูลค่ายาคืนมาให้ดู แล้วถามว่า *"amoxi ไหนสี · Mo ในรูป ไหนรูป"*
- รอบสาม ส่งภาพหน้าจอแชทของตัวเองมาให้ดูว่ามันมีแต่ข้อความ

**สามรอบกว่าแคลร์จะเข้าใจ**

**คำที่พี่กันพูด**

> *"มีรูปให้ดูมั้ย"*

> *"amoxi ไหนสี"*
> *"Mo ในรูป ไหนรูป"*

> *"ไหนรูปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปปป"*

**ทำไมถึงผิดหนัก**

มีกฎเขียนไว้ชัดอยู่แล้วในความจำหลักว่า
**"รายงานเรื่องสี/หน้าตา ต้องให้พี่กันเห็นของจริง ไม่ใช่รหัสสี"**

แคลร์ไม่ได้แค่ทำไม่ครบ แต่ **พูดว่าทำแล้ว** ทั้งที่พี่กันไม่มีทางเห็นอะไรเลย
ซึ่งแย่กว่าไม่ทำ เพราะพี่กันต้องเสียเวลาถามซ้ำสามรอบเพื่อจะรู้ว่าไม่มีรูปอยู่จริง

ก่อนหน้านั้นในวันเดียวกัน พี่กันสั่งว่า **"แคปจากเว็บจริงสิ"**
(พิมพ์มาโดยลืมสลับแป้นเป็น "c8x0kdg;h[0ib'lb")
แคลร์ตอบว่า "ถ่ายจากเว็บจริงให้เลย" แล้วก็ถ่ายด้วยเครื่องมือเดิมอีก
**คือรู้ว่าพี่กันอยากได้ภาพจริง แต่ยังใช้วิธีที่ส่งไม่ถึงพี่กันอยู่ดี**

**บทเรียน — ตั้งเป็นกฎ**

- 🔴🔴🔴 **ภาพที่ถ่ายด้วยเครื่องมือเบราว์เซอร์ในตัวช่วย พี่กันไม่เห็น**
  มันส่งกลับมาให้แคลร์ดูเพื่อตรวจงานเท่านั้น **ใช้เป็นหลักฐานให้พี่กันดูไม่ได้**
  จะส่งภาพให้พี่กันต้องมีไฟล์จริงแล้วส่งด้วยเครื่องมือส่งไฟล์
- 🔴🔴🔴 **ห้ามพูดว่า "นี่คือรูป" หรือ "นี่คือแคป" ถ้าไม่ได้ส่งไฟล์ภาพไปจริง**
  พิมพ์ข้อความบรรยายสีไม่ใช่รูป และไม่นับว่าทำตามที่สั่ง
- 🔴🔴 **พี่กันถามซ้ำ = แปลว่ายังไม่ได้สิ่งที่ขอ ไม่ใช่แปลว่าพี่กันดูไม่เจอ**
  ถามรอบที่สองต้องหยุดคิดใหม่ทันทีว่าวิธีที่ใช้อยู่มันส่งถึงพี่กันจริงไหม
  ไม่ใช่ทำวิธีเดิมซ้ำแล้วอธิบายเพิ่ม
- 🔴🔴 **ถ้าส่งภาพไม่ได้ ให้บอกตรง ๆ แล้วเสนอทางที่พี่กันดูเองได้**
  เช่นบอกลิงก์ที่เปิดได้ทันที ดีกว่าพิมพ์บรรยายแทนรูปแล้วบอกว่าเสร็จแล้ว

**เกี่ยวกับกฎเดิมที่มีอยู่แล้ว**

กฎ *"เรื่องสีต้องให้เห็นของจริง"* มีอยู่ในความจำหลักตั้งแต่ 26 ส.ค. 2569
แต่แคลร์ตีความว่า "ถ่ายภาพแล้ว = เห็นของจริงแล้ว" โดยไม่ได้ตรวจว่าภาพไปถึงพี่กันไหม
**กฎที่มีอยู่แล้วยังพลาดซ้ำได้ ถ้าไม่ได้ตรวจว่าผลลัพธ์ถึงมือพี่กันจริง**

## 4 ก.ย. 2569 · ME-DRP — "เราบอกอะไร เราให้ดูขนาดลูกศรรรรรรรรร"

**คำที่พี่กันพิมพ์**

> ขนาดลูกศร ไปดูมาว่าเว้บนั้นมันยังไง

(แคลร์ตอบไป · พี่กันแนบข้อความเดิมกลับมาแล้วถาม)

> ทำตามรึยัง

(แคลร์ไปวัดมา แล้วกลับมาถามว่าจะให้แก้ไหม)

> **เราบอกอะไร เราให้ดูขนาดลูกศรรรรรรรรรรรรรรรรรรรรรรรรรรรรรรรรร**

**ลำดับเหตุการณ์ — แคลร์ทำผิดทีละขั้น**

| รอบ | พี่กันสั่ง | แคลร์ทำ | ผิดตรงไหน |
|:--:|---|---|---|
| 1 | ยกรูปแบบตารางมาจากเว็บยาคืน | ยกมาไม่ครบ — ตกลูกศรเรียงลำดับ · ตกสีหัวคอลัมน์ตอนเอาเมาส์ชี้ · ตกวันที่แบบไทย | **ของสำคัญที่สุดไม่ได้เอามา** ทั้งที่อยู่ในไฟล์ต้นฉบับแท้ ๆ |
| 2 | "ขนาดลูกศร ไปดูมาว่าเว็บนั้นมันยังไง" | **อ่านโค้ด** แล้วตอบว่า "ตรงแล้ว 19/16px" | พี่กันสั่งให้ **ไปดู** ไม่ใช่ให้เดาจากโค้ด |
| 3 | "ทำตามรึยัง" | เปิดเว็บยาคืนวัดจริง เจอว่าหัวคอลัมน์ต่างกัน (11.5 vs 12px) แล้ว **กลับมาถามว่าจะให้แก้ไหม** | เจอความต่างแล้ว **ต้องแก้เลย** การถามซ้ำคือโยนงานคืนให้พี่กัน |

**ความผิดหลัก**

🔴 **พี่กันสั่งว่า "ไปดูมาว่าเว็บนั้นมันยังไง" = ไปดูแล้วทำให้เหมือน**
ไม่ใช่ไปวัดแล้วเอาตัวเลขมารายงาน แล้วถามว่าจะให้ทำต่อไหม

แคลร์ทำให้พี่กันต้องพิมพ์สั่ง **3 รอบ** เรื่องเดียว ทั้งที่รอบแรกก็ชัดอยู่แล้ว

**บทเรียน — ตั้งเป็นกฎ**

- 🔴🔴🔴 **"ไปดูเว็บนั้นมาว่าเป็นยังไง" = ไปดูแล้วทำให้เหมือน จบในรอบเดียว**
  ห้ามกลับมาถามว่า "จะให้แก้ไหม" เมื่อเจอความต่าง — ที่สั่งให้ไปดูก็เพราะอยากให้เหมือน
  ถามได้เฉพาะตอนที่การทำให้เหมือนจะไปขัดกฎอื่น (เช่นสีธีมของแต่ละเว็บ) แล้วต้องเสนอทางออกมาด้วย
- 🔴🔴 **"ไปดู" แปลว่าเปิดของจริงดู ไม่ใช่อ่านโค้ดแล้วเดา**
  รอบนี้อ่านโค้ดเห็นเลข 19/16 ตรงกันจริง แต่ **หัวคอลัมน์ต่างกัน** ซึ่งอ่านโค้ดคนละไฟล์ไม่มีทางเห็น
  ต้องเปิดทั้งสองเว็บแล้ววัดค่าที่เบราว์เซอร์คำนวณจริงมาเทียบกัน
- 🔴🔴 **ยกของจากเว็บอื่นมา ต้องยกมาทั้งชุด ไม่ใช่หยิบเฉพาะที่นึกออก**
  รอบนี้ก๊อป CSS มาแต่ข้าม `.tbl-sort` กับ `:hover` ทั้งที่อยู่ติดกันในไฟล์เดียวกัน
  วิธีที่ถูก: ไล่ทุกคลาสที่ขึ้นต้นด้วยชื่อระบบนั้น แล้วเช็คทีละตัวว่าเอามาครบไหม
- 🔴 **ของที่เป็น "ระบบ" ต้องมองว่ามีของประกอบอะไรบ้าง**
  ตารางไม่ได้มีแค่เส้นกับสี — มีการเรียง · ลูกศร · สถานะตอนชี้ · รูปแบบวันที่ · ปุ่มล้างการเรียง
  ถามตัวเองว่า "ผู้ใช้ทำอะไรกับของนี้ได้บ้าง" ไม่ใช่แค่ "มันหน้าตายังไง"

## 🔴🔴🔴 5 กันยายน 2569 · ME-DRP · มีสกิลอยู่แล้วแต่ไม่เปิดอ่าน ("จะมีกฎไว้ทำซากอะไร")

   **ช่องค้นหาทุกช่องต้องเรียกตัวกลางตัวเดียว (`thaibox.jsx`) ที่กันวรรณยุกต์ไทยไม่ให้โดนตัด**

**ความผิดที่แท้จริงไม่ใช่ "ทำไม่ครบ" แต่คือ "ไม่เคยเปิดอ่านก่อนลงมือ"**

- สกิล `pharmacy-web-logic` เขียนหน้าแรกไว้ว่า **"อ่านก่อนออกแบบฐานข้อมูลหรือหน้าจอที่เกี่ยวกับยาทุกครั้ง"**
- แคลร์แตะหน้าคลังยาทั้งวัน (สีชื่อยา · ตาราง · การ์ด · ช่องค้นหา 3 รอบ) **โดยไม่เปิดสกิลเลย**

**ผลที่ตามมา** — พี่กันต้องเป็นคนเดินตามเก็บกฎของตัวเองทีละข้อ
ทั้งที่จุดประสงค์ของการเขียนสกิลไว้คือ **จะได้ไม่ต้องมาบอกซ้ำ**
